# Обращения в поддержку

Пакет `@bartech/backend-support` владеет обращениями клиентов, внутренней очередью и вложениями.
Он не предоставляет внутренним сотрудникам доступ к продукции или другим данным компании.

`SupportService` проверяет контекст автора, ограничивает список личными обращениями, записывает
аудит и сохраняет вложение в случайный приватный ключ `support-quarantine/`. Состояние скачивания
ограничено результатом сканирования. `SupportAttachmentRepository` и `SupportAttachmentWorker`
передают outbox-события через BullMQ, а `ClamAvScanner` потоково отправляет содержимое ClamAV по
TCP INSTREAM. В API разрешение `support_requests` проверяется вместе с внутренней сессией при каждом
вызове.

`SupportAccessService` отдельно обслуживает семидневные grants и внутренние `ServiceSession`. Он
проверяет роль автора и область при выдаче, прекращает сессии при отзыве, истечении, завершении
внутренней auth-сессии или закрытии области. Product domain повторно проверяет grant, разрешение,
состояние компании и заведения. Проверка внутри транзакции мутации удерживает `FOR SHARE` на grant;
отзыв и завершение сессии блокируют ту же строку на изменение до фиксации. Так продуктовая запись и
отзыв доступа сериализуются в одном порядке.

Переменные `CLAMAV_HOST` и `CLAMAV_PORT` задают доступ к daemon; локальная конфигурация использует
host loopback и стандартный порт 3310. Backend API публикует ручки в `apps/backend/src/support`, а
пользовательский и внутренний UI находятся в web-срезах `support` и `internal-support`.

Состав и сроки хранения определяет
[`спецификация обращений`](../../docs/specs/2026-10-16-stage-9-support-requests-design.md).
