# Гарниры

Каталог `garnishes/` содержит чтение карточек и отдельный сценарий изменения активного гарнира.
Он не владеет созданием, архивом, удалением или HTTP-контрактом.

## Чтение

`GarnishReadService` повторно проверяет `view_products`, а repository ограничивает список и
карточку текущим заведением, типом `GARNISH` и состоянием `ACTIVE`. Карточка возвращает ID
компонентов и единиц, порядок состава и область ингредиента, чтобы форма редактирования могла
точно восстановить исходный выбор.

## Изменение

`GarnishUpdateService` повторно проверяет `manage_products`, нормализует и валидирует поля,
проверяет активный гарнир, компоненты и единицы в области заведения. `GarnishUpdateRepository`
использует общую advisory-блокировку продуктового графа, читает непосредственно использующие
гарнир активные коктейли, заменяет карточку и строки состава одной транзакцией и записывает
`product.updated` в той же транзакции.

Если изменённый гарнир используется активными коктейлями, сервис возвращает структурированный
конфликт со стабильным списком и SHA-256 отпечатком нормализованных данных и влияния. Повторный
запрос сверяет отпечаток под той же блокировкой; устаревший список требует нового подтверждения.
Нормализованно неизменённый запрос не записывается и не меняет `updatedAt`.
