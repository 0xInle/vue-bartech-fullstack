# План контролируемой очистки BarTech

**Цель:** удалить старую реализацию BarTech, сохранив продуктовые договорённости, инструкции агентов и историю Git, чтобы новый проект строился с нуля по утверждённой архитектуре.

**Основание:** `ARCHITECTURE.md`, `DEVELOPMENT_PLAN.md`, `DOCUMENTATION_MAP.md` и прямое решение пользователя отказаться от переноса кода прототипа.

## Сохраняемая область

- корневые продуктовые и технические документы;
- `AGENTS.md`;
- `.agents/skills/`;
- `.codex/agents/`;
- `.gitignore`;
- каталог `.git/` и всю историю репозитория;
- этот план очистки.

## Удаляемая область

- `frontend/` целиком, включая исходный код, конфигурацию, ресурсы, зависимости и локальное окружение;
- `backend/` целиком, включая исходный код, Prisma-схему прототипа, миграции, зависимости и локальное окружение;
- корневой `node_modules/`;
- прежние корневые `package.json` и `package-lock.json`.

Содержимое удаляемой области не переносится в новую реализацию. При необходимости оно остаётся доступным в истории Git как справочный прототип.

## Порядок выполнения

- [x] Зафиксировать ещё не добавленные продуктовые документы и актуальный `.gitignore`.
- [x] Удалить перечисленную старую реализацию и локальные зависимости.
- [x] Убедиться, что в рабочем дереве остались только документация, настройки агентов и служебные файлы Git.
- [x] Отметить очистку прототипа выполненной в `DEVELOPMENT_PLAN.md`.
- [x] Зафиксировать очистку отдельным коммитом.

## Проверка результата

- старые `frontend/`, `backend/` и `node_modules/` отсутствуют;
- прежние npm-манифесты и lock-файлы отсутствуют;
- все документы и настройки агентов присутствуют;
- Git не содержит случайно добавленных `.env`, зависимостей или секретов;
- новый программный код в рамках очистки не создаётся;
- тесты и тестовая инфраструктура не создаются и не запускаются.

Следующий отдельный шаг — детальный план этапа 1 из `DEVELOPMENT_PLAN.md` и создание чистого `pnpm`-monorepo.
