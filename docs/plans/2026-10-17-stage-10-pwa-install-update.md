# План среза этапа 10: установка PWA и ручное обновление

> **Статус:** реализация завершена; независимое read-only ревью прошло без подтверждённых замечаний.
> Установка из профиля и ручное применение новой версии используют API установленной версии
> `@vite-pwa/nuxt`. Web lint/build и `git diff --check` прошли; тесты, typecheck и браузер не
> запускались.

> **Для исполнителей:** не создавать тестовые файлы и не запускать тесты, typecheck, браузер, сервер
> или контейнеры без отдельной команды пользователя. Не выполнять commit или push. Сохранять все
> текущие изменения.

**Цель:** завершить пользовательский цикл установки IndieBar как PWA и показа готовой новой версии,
не устанавливая её автоматически во время работы пользователя.

**Архитектура:** использовать установленный `@vite-pwa/nuxt` и существующий `registerType: "prompt"`.
PWA-состояние отображается через предоставляемый модулем `$pwa`; управление установкой находится в
профиле, а предложение применить новую версию — в глобальной оболочке Nuxt. Установка доступна
только после браузерного события установки; обновление активируется только по нажатию пользователя.

**Технологии:** Nuxt 4, Vue 3, `@vite-pwa/nuxt` 1.1.1, PrimeVue 4.

**Источники:** `MVP_SCOPE.md` («Устройства и PWA»), `UI_AND_NAVIGATION.md` («PWA»),
`DEVELOPMENT_PLAN.md` (этап 10), `apps/web/nuxt.config.ts`, профиль и корневой компонент web.
API `$pwa` и `pwa.client.installPrompt` сверены с [официальной документацией Nuxt PWA]
(https://vite-pwa-org.netlify.app/frameworks/nuxt.html).

## Глобальные ограничения

- Не менять бизнес-правила и пользовательские данные.
- Не кешировать страницы API, бизнес-данные или персональные данные; область среза — установка и
  обновление service worker.
- Не перезагружать страницу и не активировать новую версию без явного действия пользователя.
- Если PWA отключена или `$pwa` недоступен (например, в dev-режиме), экран не должен падать и не
  должен показывать недоступные действия.
- Сохранять все текущие изменения; не коммитить и не пушить.
- Не создавать тестовые файлы и не запускать тесты, typecheck, браузер, сервер или контейнеры без
  отдельной команды пользователя.

## Поведение

- В профиле показывать «Установить приложение», когда `showInstallPrompt` сообщает, что браузер
  поддерживает установку. Нажатие запускает `$pwa.install()`; отклонение или завершение диалога не
  должно приводить к необработанной ошибке.
- Разрешить модулю перехватывать `beforeinstallprompt` и сохранять отказ пользователя по ключу
  локального хранилища, чтобы ненавязчивое предложение не появлялось повторно после закрытия.
- В общей оболочке показывать сообщение «Доступно обновление» при `needRefresh`. По нажатию действия
  обновления вызвать `$pwa.updateServiceWorker()`; не вызывать его автоматически.
- Не показывать PWA-действия в SSR или при отсутствии `$pwa`; не добавлять кнопку установки, когда
  браузер её не поддерживает или приложение уже установлено.
- Сохранить существующие manifest, иконку, `registerType: "prompt"` и ограниченный список
  precache-ресурсов.

## Фокус независимого ревью

- Вызов install отсутствует до события поддержки установки и не появляется для установленного PWA.
- SSR и dev-режим без `$pwa` не вызывают ошибок.
- Отклонение установки не показывает ложный успех и не ломает профиль.
- Новая версия не активируется и приложение не перезагружается без действия пользователя.
- Изменение не расширяет кеширование до API, рецептур или иных бизнес-данных.
