# План среза этапа 9: управление глобальным каталогом

> **Для исполнителей:** перед реализацией согласовать этот план. После согласования использовать
> `bartech_programmer`, затем передать результат на отдельное read-only ревью `bartech_reviewer`.
> Не запускать тесты, typecheck или браузер без отдельной команды пользователя. Шаги отмечаются
> `- [x]`.

**Цель:** дать сотруднику IndieBar с `global_catalog` возможность исправлять активные карточки
глобальных ингредиентов, управлять алиасами и сливать дубликаты, сохраняя все ссылки продукции во
всех заведениях.

**Архитектура:** прикладные операции каталога размещаются в `backend-products`, а внутренний API
использует существующие `InternalSessionGuard` и `InternalCatalogPermissionGuard`. Изменение
карточки, изменение алиасов и слияние выполняются в серверных транзакциях с записью аудита.
Интерфейс backoffice использует сгенерированный API-клиент и отдельный маршрут управления
каталогом.

**Стек:** NestJS, Prisma, PostgreSQL, Nuxt/Vue, OpenAPI, Orval и TanStack Query.

**Спецификация:** `docs/specs/2026-10-17-stage-9-global-catalog-management-design.md`.

## Глобальные ограничения

- Все маршруты требуют внутреннюю сессию `InternalUser` и отдельное разрешение `global_catalog`.
- Клиентские аккаунты не получают API для изменения глобального каталога.
- Редактировать можно только активные глобальные карточки ингредиентов.
- При слиянии каноническая карточка должна быть активной; дубликат может быть активным или
  архивным.
- Новый алиас создаётся неподтверждённым и не участвует в общем поиске и строгом сопоставлении,
  пока сотрудник отдельно его не подтвердит.
- Нормализованные значения алиасов остаются уникальными во всём глобальном каталоге.
- Слияние атомарно переносит ссылки из активной и архивной продукции всех заведений, переносит
  алиасы и значения пустых атрибутов, удаляет дубликат и записывает аудит.
- Алиасный конфликт или конфликт `catalogIdentityKey` с третьей карточкой отменяет всю транзакцию.
- Сохранять все существующие пользовательские и незакоммиченные изменения; не выполнять commit или
  push.
- Не создавать тестовые файлы или тестовую инфраструктуру. Не запускать тесты, typecheck, локальный
  сервер, контейнеры или браузер без отдельной команды пользователя.

## Фокус независимого ревью

- Подмена идентификатора карточки не позволяет читать или менять локальную карточку, другой тип
  продукта или глобальную карточку недопустимого статуса.
- Алиасы сохраняют уникальность с учётом нормализации; неподтверждённый вариант не попадает в
  поиск или строгое сопоставление.
- Параллельное редактирование после просмотра слияния не позволяет применить устаревшее решение.
- Ссылки в `ProductComponent` обновляются и для активных, и для архивных родительских продуктов
  всех заведений; состав компонентов остаётся без изменений.
- Любой конфликт или ошибка в ходе слияния оставляет карточки, алиасы, ссылки и аудит в исходном
  состоянии.

## Файловые области

- `packages/backend-products/src/catalog-management/` — новый модуль управления глобальными
  карточками, алиасами, предварительным просмотром и транзакционным слиянием.
- `packages/backend-products/src/products.module.ts`, `packages/backend-products/src/index.ts` —
  регистрация и экспорт модуля и сервиса.
- `packages/backend-products/src/catalog-review/catalog-review.repository.ts` — повторное
  использование общих правил нормализации/идентичности, если при реализации потребуется вынести
  существующую логику без изменения поведения очереди кандидатов.
- `apps/backend/src/products/internal-catalog.controller.ts` — маршруты управления каталогом рядом
  с существующими внутренними маршрутами каталога.
- `apps/backend/src/products/internal-catalog.dto.ts` — DTO поиска, чтения, редактирования,
  алиасов, предварительного просмотра и подтверждения слияния.
- `apps/backend/src/products/products-api.module.ts` — подключение только если текущей регистрации
  недостаточно.
- `apps/web/app/features/internal-catalog/composables/useInternalCatalogManagement.ts` — запросы,
  мутации и ключи кеша управления каталогом.
- `apps/web/app/features/internal-catalog/components/InternalCatalogManagementScreen.vue` — поиск,
  карточка, алиасы и сценарий подтверждения слияния.
- `apps/web/app/pages/internal/catalog/manage.vue` — защищённая страница управления каталогом.
- `apps/web/app/features/internal-catalog/README.md` и `InternalCatalogScreen.vue` — описание и
  ссылка из текущей очереди кандидатов на управление существующими карточками.
- `packages/api-client/openapi.json`, `packages/api-client/src/generated/` — обновить только
  штатной генерацией после изменения маршрутов.
- `DATA_MODEL.md`, `UI_AND_NAVIGATION.md`, `DEVELOPMENT_PLAN.md`, README затронутых пакетов —
  синхронизировать принятые правила и статус среза.

Изменения Prisma-схемы и миграция не ожидаются: существующие `Product`, `IngredientDetails`,
`ProductAlias`, статусы, ссылки и таблицы аудита покрывают описанные операции. Если реализация
обнаружит необходимое изменение схемы, остановить эту часть и сверить его со спецификацией до
изменения модели.

## План работ

### 1. Чтение и редактирование глобальных карточек

- [x] Добавить в модуле управления каталогом постраничный поиск глобальных ингредиентов по
      официальному названию и подтверждённым алиасам. Для выбора канонической карточки разрешать только
      `ACTIVE`; для поиска дубликата показывать оба статуса.
- [x] Добавить просмотр карточки с атрибутами, категорией и алиасами. Исключить клиентские компании,
      заведения и содержимое рецептур из API-ответов.
- [x] Добавить редактирование `name`, `categoryCode`, `brand`, `strength`, `country` и
      `externalIdentifier`. Проверять активный глобальный ингредиент, активную категорию, формат и
      обязательные поля; пересчитывать нормализованные поля и `catalogIdentityKey` теми же правилами,
      что использует создание глобального ингредиента.
- [x] На конфликт уникального ключа возвращать понятный конфликт без частичного изменения. Успешную
      правку записывать в `AuditEvent` и `InternalAuditEvent` внутри той же транзакции.

### 2. Управление алиасами

- [x] Добавить создание алиаса на активной глобальной карточке: нормализовать исходное значение,
      вычислить `valueNormalized` и `searchValueNormalized`, устанавливать `isConfirmed = false`.
- [x] Добавить отдельное подтверждение существующего алиаса. Проверять принадлежность алиаса
      глобальному ингредиенту и не разрешать подтверждать карточку в архиве.
- [x] Добавить удаление алиаса с проверкой глобального владельца. Конфликт уникальности значения
      другого алиаса возвращать как конфликт без изменения данных.
- [x] Записывать успешное создание, подтверждение и удаление в оба журнала аудита с внутренним
      автором и идентификаторами карточки/алиаса. Не включать пользовательские рецептуры в metadata.

### 3. Предварительный просмотр и атомарное слияние

- [x] Добавить предварительный просмотр пары карточек. Каноническая карточка должна быть активным
      глобальным ингредиентом; дубликат — активным или архивным глобальным ингредиентом; ID должны быть
      разными. Возвращать значения обеих карточек, итог заполнения пустых полей, статус алиасов,
      конфликты и количество ссылок в `ProductComponent` по всем заведениям, не раскрывая названия
      заведений и рецептуры.
- [x] Включить `updatedAt` обеих карточек в результат предварительного просмотра. При подтверждении
      клиент передаёт ожидаемые значения; сервер в транзакции блокирует карточки и повторно сравнивает
      версии. При изменении между просмотром и подтверждением вернуть конфликт, требующий нового
      просмотра и подтверждения.
- [x] Реализовать слияние одной Prisma-транзакцией: проверить карточки и статусы; заполнить только
      пустые атрибуты канонической карточки; перенести все алиасы, сохраняя `isConfirmed`; добавить имя
      дубликата как подтверждённый алиас, кроме случая, когда его нормализованное значение совпадает с
      официальным названием канонической карточки; обновить ссылки на дубликат во всех
      `ProductComponent` (включая активных и архивных родителей любых заведений); удалить дубликат;
      записать аудит.
- [x] До записи выявлять конфликт уникального нормализованного алиаса, включая имя дубликата, с
      третьей карточкой, и конфликт итогового `catalogIdentityKey`. Возвращать идентификатор и
      безопасные сведения карточки-конфликта без изменения данных.
- [x] Конфликт и любая ошибка БД должны откатывать также перенос атрибутов, алиасов и ссылок;
      событие аудита записывать в транзакции только после успешной валидации всех конфликтов.

### 4. Внутренний API и OpenAPI
