# План реализации: рабочий статус коктейля

> Статус: реализация завершена; статические проверки пройдены.

**Цель:** добавить рабочие статусы «Активен» и «Проработка» коктейлям в форме, списке, карточке, поиске и выгрузках.

**Спецификация:** `docs/specs/2026-10-28-cocktail-workflow-status.md`.

## Обязательные правила

- Архивное состояние и рабочий статус коктейля хранятся и обрабатываются раздельно.
- Миграция отмечает существующие коктейли как «Активен», новые по умолчанию получают «Проработка».
- Пакетный экспорт включает оба статуса неархивных коктейлей; PDF и структурированная выгрузка сохраняют статус.
- API-клиент обновляется только через `pnpm api:generate`.
- Перед UI-работой сверить `UI_COMPONENT_STYLES.md`, сценарии `UI_AND_NAVIGATION.md` и существующие образцы компонентов.
- Не создавать и не запускать тесты, не запускать typecheck, сервер или браузер без отдельной команды пользователя. Разрешены форматирование, lint и build. Пользователь разрешил применение миграции к тестовой БД.
- Сохранить параллельные пользовательские изменения.

## Задачи реализации

### 1. Модель и миграция

- Добавить enum рабочего статуса коктейля и поле в типизированные детали коктейля.
- Создать миграцию: заполнить существующие записи значением `ACTIVE`, затем задать `IN_DEVELOPMENT` по умолчанию новым деталям.
- Проверить, что архивирование и восстановление меняют только состояние архива.

### 2. Backend и API

- Добавить статус в DTO создания/изменения, чтения списка и карточки; по умолчанию на сервере — `IN_DEVELOPMENT`.
- Добавить необязательный фильтр списка со значением по умолчанию, соответствующим показу всех статусов.
- Передавать рабочий статус в общий поиск, не менять ограничение неархивными продуктами.
- Сохранить статус в одиночной и пакетной PDF-выгрузке и в структурированных данных.
- Проверить серверные ограничения доступа и совместимость типов.
- Сгенерировать API-клиент штатной командой.

### 3. Интерфейс

- Добавить поле статуса рядом с названием в общей форме создания/редактирования коктейля.
- Добавить пустой по умолчанию фильтр статуса рядом с фильтром категории; пустое значение показывает все статусы, состояние фильтра синхронизировать с URL.
- Показать статусы в строках таблицы, мобильных карточках, карточке коктейля и общем поиске; для «Проработка» применить жёлтый `warn`.
- Добавить метку «Проработка» в результаты главного поиска.
- Проверить соответствие компонентов стилевому справочнику и существующим образцам.

### 4. Документация и статические проверки

- Синхронизировать профиль продуктовой модели, MVP, концептуальную модель и UI-сценарии.
- Обновить README затронутых модулей, если в них описываются изменённые контракты.
- Выполнить Prettier только для изменённых файлов, подходящий lint и build, если их область не затрагивает посторонние файлы; выполнить `git diff --check`.
- Не утверждать визуальную проверку: браузер по умолчанию не запускать.
