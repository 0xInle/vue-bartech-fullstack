# План реализации: рабочая навигация и управление заведениями

> **Для исполнителя:** обязательный поднавык для нативного выполнения — `superpowers:executing-plans`. Начинать выполнение только после согласования этого плана и выбора пользователем способа исполнения. Все шаги отмечаются флажками `- [x]`.

**Цель:** упростить рабочую навигацию, перенести действия закрытия с главной и предоставить бар-менеджеру единый экран для доступных ему заведений, приглашения менеджера и самостоятельного открытия нового заведения.

**Архитектура:** рабочая оболочка группирует ссылки через PrimeVue `PanelMenu`, сохраняя постоянную desktop-панель и мобильный Drawer для дополнительных разделов. Экран управления использует только рабочие пространства текущего пользователя с соответствующими разрешениями; прямое создание заведения выполняется новой серверной операцией, которая атомарно создаёт заведение и членство бар-менеджера. Существующие потоки локальной команды, шеф-барменов и закрытия переиспользуются и остаются разделёнными по области действия.

**Технологии:** Nuxt 4, Vue 3, PrimeVue 4, Tailwind CSS, TanStack Query, NestJS 11, Prisma, OpenAPI и Orval.

**Спецификация:** `docs/specs/2026-10-17-workspace-navigation-and-venue-management-design.md`.

## Глобальные ограничения

- Не менять утверждённые бизнес-права, роли и области доступа.
- Не перечислять и не показывать бар-менеджеру заведения, к которым у него нет рабочего доступа.
- Разрешение проверяется сервером при каждом запросе; скрытие пункта меню не является защитой.
- Не создавать тестовые файлы, тестовую инфраструктуру или тестовые зависимости.
- Не запускать unit-, integration- и e2e-тесты, `typecheck`, браузер, сервер или контейнеры.
- Форматировать только изменённые файлы командой `pnpm exec prettier --write <пути-к-файлам>`.
- Сохранить незакоммиченное пользовательское изменение `packages/database/src/index.js`.
- Не вызывать проектных агентов автоматически; отдельное ревью выполнять только по прямому запросу пользователя или если оно будет отдельно согласовано.

## Области файлов

- `apps/backend/src/organizations/organizations.controller.ts` — DTO и защищённый маршрут самостоятельного создания дополнительного заведения.
- `packages/backend-organizations/src/organizations.service.ts` — серверная проверка полномочий и транзакционное создание заведения с ролью бар-менеджера.
- `apps/web/app/features/organizations/composables/useVenueManagement.ts` — создание заведения и список управляемых рабочих пространств текущей компании.
- `apps/web/app/features/organizations/components/VenueManagementScreen.vue` — список заведений, самостоятельное создание, приглашения и действия закрытия.
- `apps/web/app/features/organizations/components/VenueManagementPageScreen.vue` и маршрут `apps/web/app/pages/app/companies/[companyId]/venues/[venueId]/management.vue` — загрузка рабочего контекста и оболочка страницы.
- `apps/web/app/features/organizations/components/OrganizationLifecyclePanel.vue` — явная передача целевых ID компании и заведения для закрытия из экрана управления.
- `apps/web/app/features/team/components/TeamManagementScreen.vue` — объединённая страница локальной команды и шеф-барменов.
- `apps/web/app/features/team/components/ChefTeamSection.vue` — самостоятельный блок шеф-барменов компании с существующим API приглашений.
- `apps/web/app/features/team/components/CompanyChefManagementScreen.vue`, `CompanyChefPageScreen.vue` и `apps/web/app/pages/app/companies/[companyId]/venues/[venueId]/chefs.vue` — удаление отдельного экрана и перенаправление старого маршрута на команду.
- `apps/web/app/features/workspace/components/WorkspaceShell.vue` и `apps/web/app/features/workspace/components/VenueHomeScreen.vue` — навигация, блок текущего контекста и очищенная главная.
- `apps/web/nuxt.config.ts` — включение `PanelMenu` в список PrimeVue-компонентов.
- `apps/web/app/features/workspace/README.md`, `apps/web/app/features/team/README.md`, `apps/web/app/features/organizations/README.md`, `UI_AND_NAVIGATION.md` — описание актуальной структуры и потоков.
- `packages/api-client/openapi.json` и `packages/api-client/src/generated/**` — только результат штатной генерации API-клиента.

## Обзорная проверка

Перед реализацией подтвердить по текущему коду, что перечисленные права и формы ответов совпадают с фактическими API-контрактами. Новая операция создаёт только заведение в существующей компании и локальное членство `BAR_MANAGER`; она не создаёт `CompanyMembership` и не меняет роли пользователя в других заведениях. Проверить, что перенос компонента закрытия сохраняет действующие проверки экспорта, точного названия, подтверждения и ограничений по компании.

## Фокус ревью

- Если у пользователя есть несколько ролей в одной компании, список управления содержит только рабочие пространства с полномочиями, а не все членства.
- Самостоятельное создание проверяет разрешение и активное состояние компании на сервере; подмена `companyId` не создаёт заведение в чужой компании.
- Повтор названия заведения возвращает конфликт без дублирования членства и частично созданных данных.
- Создание заведения добавляет бар-менеджера только в новое заведение и сохраняет его роли в остальных местах.
- Перенос панели закрытия сохраняет адресное закрытие выбранного заведения, существующий выбор выгрузки и доступное только уполномоченной роли закрытие компании.
- На мобильном устройстве группировка не удаляет доступные разделы, а Drawer сохраняет текущий контекст и профиль.

Автоматические проверки для этих случаев не создаются по правилам проекта. Их нужно учитывать при последующем независимом ревью и ручной приёмке, если пользователь отдельно разрешит её.

## Не выполняется этим планом

- Настройка и отдельное переосмысление сценариев шеф-бармена, кроме сохранения доступа к объединённой команде и закрытию компании.
- Новые права, роли, модели членства и видимость чужих заведений.
- Браузерная проверка, запуск локального сервера и ручная визуальная приёмка.
- Коммит или отправка изменений в удалённый репозиторий.
