# План: интерфейс страницы команды и единое приглашение сотрудников

## Цель

Упростить экран «Команда»: оставить заголовок текущего раздела, список сотрудников в компактной таблице PrimeVue и одно действие «Пригласить», открывающее Drawer. В Drawer объединить создание доступных пользователю приглашений и просмотр ожидающих приглашений, сохраняя фактическую область действия каждой должности.

## Подтверждённые требования

- Скрыть кнопку глобального поиска на широком десктопном экране. Оставить её доступной на телефонах и планшетах.
- Удалить с экрана команды подпись с названием компании и название заведения из заголовка. Заголовок экрана — «Команда».
- Разместить рядом с заголовком компактную кнопку «Пригласить». Она открывает PrimeVue `Drawer`.
- В Drawer разместить поле электронной почты, выбор должности, кнопку отправки приглашения и список ожидающих приглашений.
- Для ожидающего приглашения показать email, должность и дату окончания. Для наглядной проверки интерфейса добавить одно явно демонстрационное приглашение.
- После заголовка показать раздел «Сотрудники» и штатную PrimeVue `DataTable` малого размера с колонками «ФИО» и «Должность».
- Визуальный образец таблицы — `WorkspaceProductSearchResults.vue`: штатные стили PrimeVue v4, `size="small"`, цвет линий как у текущих линий таблицы, компактная типографика без самодельного переоформления всего компонента.
- Для элементов PrimeVue использовать минимальный подходящий размер (`small`).
- На экране команды сохранить текущие возможности управления участниками и отзывом приглашений, если они доступны пользователю.

## Уточнение данных приглашения

Текущий контракт приглашения содержит email, должность/тип приглашения и срок действия — этого достаточно для требуемого отображения. Один демонстрационный ряд приглашения добавляется только в режиме разработки (`import.meta.dev`) и визуально помечается как пример; он не должен попадать в production-сборку, API, сохранённое состояние или реальные действия отзыва.

## Сохранение областей доступа

Единый интерфейс не означает единый backend-контекст. Приглашение шеф-бармена остаётся приглашением уровня компании, остальные доступные должности приглашаются в текущее заведение. Список ролей определяется существующими разрешениями и правилами ролей. Пользователь выбирает должность, но не техническую цель приглашения. Создание нового заведения через приглашение бар-менеджера остаётся в разделе управления заведениями: это отдельный сценарий создания пространства.

На странице сотрудников этой итерации основным источником таблицы остаётся список текущего заведения. Состав шеф-барменов компании сохраняет свою отдельную область данных и может быть показан отдельным подзаголовком/таблицей, если текущая модель страницы уже предоставляет его; удалять состав шеф-барменов ради объединения формы приглашения нельзя.

2. Перенести desktop/mobile trigger глобального поиска на соответствующие брейкпоинты.

4. Компоновочно перенести форму и список ожидающих приглашений в Drawer; соединить текущие venue/company операции с единым выбором роли без изменения областей доступа.
5. Заменить представление участников текущего заведения на PrimeVue `DataTable` `size="small"`, сохранив действия редактирования и адаптивность.
6. Добавить изолированный dev-only пример ожидающего приглашения для визуальной проверки.
7. Синхронизировать `UI_AND_NAVIGATION.md` и README команды с фактическим интерфейсом.
8. Отформатировать только изменённые файлы Prettier и выполнить lint/build; автоматические тесты, typecheck и браузерную проверку не запускать без отдельной команды пользователя.

## Критерии готовности

- На десктопе у правого верхнего края нет кнопки глобального поиска; на телефоне и планшете она открывает прежний Drawer.
- На Team отображается заголовок «Команда» без названия компании и заведения.
- Кнопка «Пригласить» рядом с заголовком открывает Drawer с почтой, ролью, отправкой и ожидающими приглашениями.
- В реальных данных приглашения показывают email, должность и срок окончания. Демонстрационный ряд приглашения виден только в режиме разработки и помечен как пример.
- Сотрудники отображаются в PrimeVue DataTable малого размера с колонками «ФИО» и «Должность»; выбор строки сохраняет доступное управление участником.
- Шеф-бармен приглашается в компанию, остальные роли — в текущее заведение; ограничения по разрешениям остаются на сервере.
- Раздел команды не теряет список компании шеф-барменов, отзыв приглашений и текущие действия управления.
- В проектной документации описан актуальный UI.

## Риски и ограничения

- В рабочем дереве на момент составления плана присутствуют незавершённые изменения регистрации, ролей и приглашений. Разработчик должен встроиться в их текущее состояние, не откатывать и не переформатировать несвязанные изменения.
- Макет мобильной таблицы может требовать горизонтальной прокрутки или адаптивного шаблона строк. Следует сохранить читаемость без изменения общего визуального языка PrimeVue; финальное решение проверить на поддерживаемой ширине экрана.
