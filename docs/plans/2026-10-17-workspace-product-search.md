# Поиск продукции с Главной — план реализации

> **Для исполнителя:** реализовать план по задачам, сверяясь со спецификацией и сохраняя несвязанные пользовательские изменения.

**Цель:** добавить Главной основной поиск активной продукции и обеспечить быстрый доступ к нему с других экранов, ограничив область текущим заведением для локальных ролей и всей компанией для шеф-бармена.

**Архитектура:** текущий поиск форм для состава остаётся на существующем `useProductSearch` и `scope=COMPONENT`. Для пользовательского поиска добавляется отдельная frontend-логика с выбором области и единым списком результатов. Межзаводской поиск и получение карточек выполняются через серверные endpoints, которые проверяют членство шеф-бармена в компании; продукт другого заведения открывается в режиме чтения в Drawer и не меняет текущий контекст.

**Стек:** Nuxt 4, Vue 3, PrimeVue 4.5.5, TanStack Vue Query, NestJS 11, Prisma, Orval API client.

**Спецификация:** `docs/specs/2026-10-17-product-search-design.md`.

## Общие ограничения

- Backend повторно проверяет компанию, заведение, членство и полномочия на каждом запросе.
- Роли бармена, старшего бармена и бар-менеджера ищут в выбранном заведении; шеф-бармен может включить поиск по всей своей компании.
- Поиск содержит только активные продукты и доступные заведению глобальные ингредиенты; архив остаётся в разделе архива.
- Результаты содержат название и тип; причина совпадения не отображается. Название заведения показывается при поиске по компании.
- Ингредиент показывается в результатах, но пока не открывает карточку или страницу.
- Карточка продукта другого заведения открывается только для чтения в PrimeVue `Drawer`; рабочий контекст остаётся прежним.
- Не создавать тестовые файлы или инфраструктуру и не запускать unit-, integration- и e2e-тесты.
- Не запускать `typecheck`, локальный сервер или браузерную проверку без отдельной команды пользователя.
- Разрешены `lint`, `build`, генерация API и форматирование только затронутых файлов через `pnpm exec prettier --write <пути-к-файлам>`.
- Не менять `packages/database/src/index.js` и другие существующие пользовательские изменения вне этого объёма.

## Области изменений

- `apps/backend/src/products/`: DTO, контроллеры и регистрация новых company-scope search/read endpoints.
- `packages/backend-products/src/search/`: серверная проверка области поиска и SQL-поиск, ограниченный одной компанией; ответ межзаводского поиска содержит название заведения.
- `packages/backend-organizations/src/organizations.service.ts`: серверная проверка активного членства шеф-бармена в компании, если подходящего публичного метода нет.
- `apps/web/app/features/products/`: отдельный composable пользовательского поиска, интерфейс строки/результатов и Drawer карточки другого заведения.
- `apps/web/app/features/workspace/components/WorkspaceShell.vue` и `VenueHomeScreen.vue`: доступ с любого рабочего экрана и крупный поиск на Главной.
- `packages/api-client/`: обновлённые OpenAPI и сгенерированный клиент; сгенерированные файлы не редактировать вручную.
- `UI_AND_NAVIGATION.md`, `PRODUCT_MODEL.md`, `MVP_SCOPE.md`: уточнить фактическое поведение поиска и чтения карточки между заведениями, если реализация выявит расхождение.

## Проверяемые риски

- Подмена `companyId`, `venueId` или идентификатора продукта не раскрывает сведения вне компании, в которой пользователь состоит шеф-барменом.
- При переключении между компаниями, заведениями, областью и запросами кеш не показывает результаты предыдущего контекста.
- У бармена и бар-менеджера нет возможности расширить поиск параметрами клиента на другие заведения.
- Выбор продукта из другого заведения не меняет URL/рабочее пространство и не показывает действия редактирования, архивации или экспорта.
- Результат-ингредиент не выглядит интерактивным переходом.
- Пустой запрос, ввод короче двух символов, пустой результат, загрузка и ошибка имеют отдельные состояния; старый ответ не подменяет результат более нового запроса.

- Создать `apps/web/app/features/products/components/WorkspaceProductSearch.vue` для поиска, фильтров типов и состояний загрузки/ошибки/пустого результата.
- Создать `apps/web/app/features/products/components/ProductSearchResultDrawer.vue` для карточки результата из другого заведения, только для чтения.
- Изменить `apps/web/app/features/workspace/components/VenueHomeScreen.vue` и `WorkspaceShell.vue` для крупного поля на Главной и доступа к поиску с остальных рабочих экранов.
- При необходимости изменить `apps/web/app/features/products/types.ts` для типизации результата и нормализации ответа.

**Шаги:**

- [ ] На Главной отобразить крупный поиск; не выводить аналитические блоки, недавние элементы или дополнительное содержимое до ввода запроса.
- [ ] На десктопе дать открыть поиск с любого рабочего экрана из верхней части основной области; на мобильном открывать его в полноэкранном PrimeVue `Drawer`.
- [ ] Отправлять запрос после двух символов, ограничивать длину 160 символами и поддержать быстрые фильтры «Все», «Коктейли», «Заготовки», «Гарниры», «Ингредиенты».

- [ ] Для шеф-бармена добавить явный переключатель «Все заведения компании»; по умолчанию область — текущее заведение. Другим ролям не отображать переключатель.
- [ ] В компании показывать название заведения у локальных результатов. Для результата текущего заведения переходить на существующий маршрут карточки коктейля, заготовки или гарнира; ингредиент оставить строкой без действия.
- [ ] Для продукта другого заведения шеф-бармена открыть read-only Drawer с названием заведения, сохранить текущие route/workspace и скрыть управляющие действия.
- [ ] Передавать `AbortSignal` в запросах, не показывать устаревшие результаты после смены контекста и не разделять кеш между компаниями.
- [ ] Не менять `useProductSearch.ts` и поиски выбора компонентов, если для интеграции нет необходимой причины.
