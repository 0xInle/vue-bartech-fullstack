**Цель:** дать внутренним сотрудникам с разрешением `internal_audit` защищённый постраничный просмотр
`InternalAuditEvent`, не раскрывая произвольные метаданные и клиентский `AuditEvent`.

**Архитектура:** read-only API размещается в отдельном модуле backend и на каждом запросе требует
`InternalSessionGuard` и отдельный permission guard `internal_audit`. Экран backoffice запрашивает
события страницами по 50, от новых к старым, с устойчивым курсором по `(createdAt, id)`. Ответ
содержит только явно разрешённые поля; произвольное поле `metadata` не сериализуется.

**Стек:** NestJS, Prisma, PostgreSQL, Nuxt/Vue, OpenAPI, Orval и TanStack Query.

**Источники:** `MVP_SCOPE.md`, `DATA_MODEL.md`, `UI_AND_NAVIGATION.md`, `ARCHITECTURE.md`,
`DEVELOPMENT_PLAN.md` (этап 9), модель `InternalAuditEvent` в `packages/database/prisma/identity.prisma`.

## Глобальные ограничения

- Разрешение `internal_audit` является единственным разрешением для просмотра журнала.
- Backend повторно проверяет внутреннюю сессию и разрешение при каждом запросе.
- Читается только `InternalAuditEvent`; записи пользовательского `AuditEvent` не включаются.
- Ответ не включает `metadata`, содержимое техкарт, имена продуктов, обращения, вложения, пароли,
  токены, TOTP-секреты или recovery-коды.
- Список доступен только для чтения; редактирование и удаление событий не добавляются.
- Не менять сроки хранения событий и модели бизнес-аудита.
- Сохранять незакоммиченные изменения; не выполнять commit или push.
- Не создавать тестовые файлы и не запускать тесты, typecheck, браузер, сервер или контейнеры без
  прямой просьбы пользователя.

## Контракт списка

Каждый элемент возвращает `id`, `createdAt`, `eventType`, `actorType`, nullable email связанного
`InternalUser`, `companyId`, `venueId` и `serviceSessionId`. Если внутреннего пользователя нет,
интерфейс показывает локализованное название типа актора (`Оператор`, `Система` или общий вариант),
не пытаясь получить данные внешнего пользователя из `metadata.actorId`.

Ответ страницы содержит `items` и nullable `nextCursor`. Курсор непрозрачен для клиента и кодирует
`createdAt` вместе с `id`; порядок — `createdAt DESC, id DESC`. Размер страницы по умолчанию — 50,
сервер ограничивает его значением 100. Интерфейс показывает время, тип события, актора и имеющиеся
ID области/сессии, предлагает загрузить следующую страницу и отображает состояния загрузки, ошибки
и пустого журнала. Фильтры, поиск, раскрытие `metadata`, экспорт и просмотр клиентской истории в
этот срез не входят.

## Фокус независимого ревью

- Запрос без внутренней сессии или `internal_audit` не читает журнал и не раскрывает его наличие.
- Курсор не пропускает и не дублирует записи при одинаковом `createdAt`.
- API не возвращает произвольное `metadata`, клиентский `AuditEvent` или внешний `actorId` как
  идентифицирующую информацию.
- Интерфейс не делает запрос до загрузки auth-сессии и при отсутствии разрешения.
- Пустая и последняя страница не создают бесконечную загрузку или дубли.
