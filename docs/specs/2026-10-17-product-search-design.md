# Поиск продукции с Главной

## Цель

Сделать поиск главным способом начать работу с продукцией: с Главной пользователь сразу может найти нужную активную техкарту или ингредиент и открыть результат.

## Размещение

- На Главной отображается поле поиска; после ввода запроса на этом же экране появляется таблица результатов. Видимый заголовок «Поиск продукции» не показывается.
- На компьютере поиск также доступен из верхней панели любого рабочего экрана.
- На Главной поле поиска и результаты остаются на странице при любой ширине экрана. На телефоне с остальных рабочих экранов поиск открывается в полноэкранном представлении по отдельной кнопке «Поиск» с иконкой.
- Поле поиска не сопровождается дублирующими карточками разделов, счётчиками, графиками или лентой недавно открытого.

## Область и права

- Бармен, старший бармен и бар-менеджер ищут в текущем выбранном заведении. Бар-менеджер сначала переключает рабочее пространство, если ему нужно искать в другом заведении.
- Шеф-бармен может явно включить поиск по всем заведениям своей компании; результат из другого заведения показывает его название.
- Поиск по текущему заведению включает активные локальные продукты и доступные этому заведению глобальные ингредиенты. Архив ищется отдельно в разделе архива.
- Backend самостоятельно проверяет компанию, заведение, членство и полномочия; клиент не расширяет область поиска фильтрацией.

## Поисковый запрос и результаты

- Единый поиск поддерживает коктейли, заготовки, гарниры и ингредиенты.
- Учитываются название и отображаемое название категории, состав, технология приготовления, бокал, лёд и метод приготовления; правила нормализации, алиасов, опечаток и транслитерации остаются в `PRODUCT_MODEL.md`.
- Результаты выводятся таблицей PrimeVue по релевантности с колонками «Наименование» и «Категория»; в колонке «Категория» указывается тип результата: ингредиент, коктейль, заготовка или гарнир.
- После выполнения поиска на экране остаются строка поиска и таблица результатов. Фильтры по типу продукции и системной категории не показываются.
- Таблица использует PrimeVue v4 `DataTable`, режим `Row Selection Single` и размер `small`. Выбор строки коктейля, заготовки или гарнира сохраняет переход к соответствующей карточке; выбор ингредиента не открывает отдельную страницу.
- На экране показываются первые 20 совпадений. Пагинации нет; чтобы найти другой продукт, пользователь уточняет поисковый запрос.
- Причина совпадения пользователю не показывается.
- При поиске по всей компании у результата дополнительно показывается заведение. Компания и текущий контекст не дублируются.
- Выбор коктейля, заготовки или гарнира текущего заведения открывает существующую карточку. Результат другого заведения в режиме шеф-бармена открывает карточку только для чтения в PrimeVue `Drawer`, не переключая текущее рабочее пространство; панель показывает название заведения и не предлагает редактирование или другие действия. Результат-ингредиент показывается в списке, но пока не открывает отдельную карточку или страницу.

## Состояния

- До ввода достаточного запроса экран не показывает фиктивные результаты и дополнительные дашборд-блоки.
- Запрос отправляется после ввода не менее двух символов; максимальная длина — 160 символов.
- Поиск выполняется автоматически с debounce; отдельной кнопки отправки запроса нет.
- При вводе нового текста старые данные не выдаются как результат нового состояния.
- Во время запроса используется общий `LoadingIndicator`.
- Пустой результат, ошибка запроса и обычное состояние списка имеют отдельное понятное представление.
- Поиск не показывает недоступные записи, архивные продукты или продукты из других заведений в режиме текущего заведения.

## Текущее техническое состояние и необходимая работа

- Существующий пользовательский API `/organizations/companies/:companyId/venues/:venueId/products/search` и `scope=WORKSPACE` покрывает поиск по активным продуктам одного выбранного заведения, включая глобальные ингредиенты.
- Пользовательские endpoint поиска по заведению и компании принимают `limit`; интерфейс запрашивает первые 20 результатов без фильтров типа и категории. Существующий endpoint с `scope=COMPONENT` сохраняет array-контракт и текущую работу выбора компонентов в формах.
- Интерфейс не загружает всю выдачу и не предоставляет пагинацию: отображаются первые 20 результатов.
- `useProductSearch` сейчас отправляет `scope=COMPONENT`; этот режим предназначен для подбора компонентов в формах и не должен определять поведение главного поиска.
- Для режима шеф-бармена требуется серверный поиск по заведениям компании с повторной проверкой действующего членства и полномочий. Запрос не должен принимать произвольный список чужих заведений от клиента.
- Сохраняется текущий формат `matchReason` для внутреннего ранжирования и других потребителей. UI поиска не отображает это поле; расширять его enum ради причины совпадения не нужно.
- Для результата-ингредиента не требуется переход или загрузка карточки; отдельный маршрут просмотра ингредиента не входит в эту задачу.
- Для продукта другого заведения нужен серверный запрос его карточки только для чтения с повторной проверкой членства шеф-бармена в компании; открытие панели не меняет компанию или заведение в URL и клиентском контексте.

## Ограничения

- Не менять правила ролей, кроме уже утверждённой области поиска, отражённой в `PRODUCT_MODEL.md`, `MVP_SCOPE.md` и `UI_AND_NAVIGATION.md`.
- Не добавлять аналитику, недавно просмотренные карточки, метрики, избранное, историю запросов или редактирование ингредиентов из поиска.
- Не менять существующие формы поиска внутри списков и компонентов рецепта за пределами переиспользования общих типов/логики без необходимости.
- Не добавлять тестовые зависимости или инфраструктуру без отдельного согласования.

## Проверка

- Выполнить форматирование затронутых файлов.
- Запустить разрешённые статические проверки (`lint`, `build`), если область изменений понятна.
- Не запускать тесты, `typecheck`, сервер или браузерную проверку без отдельной команды пользователя.
