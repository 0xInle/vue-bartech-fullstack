# Актуализация формы создания ингредиента из поиска

## Цель

Если пользователь закрыл выпадающий поиск и изменил запрос, следующая форма создания локального ингредиента должна получить новый запрос как исходное название. Подпись «Ингредиент не найден» должна быть компактной.

## Границы

- Не менять поиск, создание ингредиента на сервере и выбранную категорию.
- Закрытие выпадающего окна снаружи сбрасывает открытую inline-форму.
- Повторное открытие формы берёт актуальный текст поиска.
- Ручное изменение названия сохраняется, пока пользователь не закрыл форму.
- Подпись результата отсутствия поиска уменьшается до вспомогательного размера.

## Варианты

1. Обновлять название формы при каждом изменении поискового запроса. Это может перезаписать название, которое пользователь уже редактирует.
2. Сбрасывать форму при закрытии выпадающего окна и инициализировать её актуальным запросом при следующем открытии. Выбран этот вариант, потому что он сохраняет ручные правки в активной форме и не переносит устаревшее значение в новую попытку.

## Ожидаемое поведение

После закрытия выпадающего окна форма скрыта. При новом запросе без результатов отображается предложение создать ингредиент; по нажатию форма открывается с новым запросом в поле названия. Категория и другие поля новой формы начинаются с исходного состояния. Если пользователь редактирует название в открытой форме, ввод не синхронизируется с поисковой строкой.

## Область реализации

Изменить только состояние inline-создания в `CocktailComponentRows.vue` и размер текста состояния отсутствия результатов в этом же компоненте. Сверить поведение `AutoComplete` по текущей обёртке `IngredientSelector.vue`; серверные сценарии не затрагивать.

## Проверка

Статически проверить сборку и lint изменённого frontend-кода. Не добавлять и не запускать тесты; визуальную проверку в браузере выполняет пользователь.
