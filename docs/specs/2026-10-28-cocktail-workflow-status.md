# Рабочий статус коктейля

## Цель

Добавить коктейлю рабочие статусы «Активен» и «Проработка», чтобы команда могла вести рецепт от создания до введения в меню. Рабочий статус не заменяет состояние архива и не меняет права на продукцию.

## Согласованное поведение

- Новый коктейль по умолчанию получает статус «Проработка».
- В форме создания и редактирования доступен выбор «Активен» / «Проработка» рядом с полем «Название».
- В списке коктейлей фильтр по статусу располагается рядом с фильтром категории; по умолчанию поле пустое и показываются все статусы.
- В таблице, карточке и общем поиске статус «Проработка» показывается жёлтым чипом предупреждения severity `warn`; «Активен» сохраняет зелёный тон.
- Основной поиск показывает неархивные коктейли обоих статусов. Результаты «Проработка» явно помечаются.
- Пакетная выгрузка включает все неархивные коктейли, в том числе «Проработка». Архивные карточки по-прежнему включаются только по текущему явному выбору.
- При архивировании и восстановлении рабочий статус сохраняется.

## Модель данных и совместимость

Состояние архива остаётся отдельным полем продукта. Рабочий статус хранится в деталях коктейля, поэтому он применим только к коктейлям и не смешивается с архивом.

Для существующих коктейлей миграция устанавливает «Активен». Значение по умолчанию «Проработка» применяется только к новым коктейлям. Для не-коктейлей рабочий статус отсутствует.

## Поиск и выгрузка

Поиск не расширяется на архивные карточки. В поисковый DTO добавляется nullable рабочий статус коктейля; для других типов он отсутствует. Интерфейс отображает метку «Проработка» в результате.

Пакетный экспорт использует текущую область неархивных карточек и тем самым включает оба рабочих статуса коктейлей. Структурированная резервная выгрузка сохраняет рабочий статус в данных карточки. PDF отдельной и пакетной выгрузки явно отображает рабочий статус коктейля, чтобы распечатка сохраняла контекст готовности.

## Область реализации

- Prisma-модель, миграция с заполнением статусов существующих коктейлей и значение по умолчанию для новых.
- Backend DTO, сервисы, чтение списка и карточки, фильтрация, поиск и сериализация выгрузки.
- OpenAPI и регенерация публичного API-клиента штатной командой.
- Форма коктейля, список/фильтр, карточка, метка общего поиска.
- Обновление `PRODUCT_MODEL.md`, `MVP_SCOPE.md`, `DATA_MODEL.md` и `UI_AND_NAVIGATION.md`.

## Границы

- Не добавляются черновики, третий статус, отдельная публикация или новые права.
- Архивные правила и разрешения не меняются.
- Статус «Проработка» не исключается из пакетной выгрузки.
- Не меняется поиск архивных карточек и доступность продукции в других сценариях.

## Критерии готовности

- Создание коктейля без явного выбора сохраняет «Проработка».
- Изменение статуса работает при редактировании и видно в списке и карточке.
- Фильтр по умолчанию показывает оба статуса и корректно работает при выборе каждого из них.
- Поиск показывает «Проработку» с меткой, не возвращая архивные карточки.
- Пакетная выгрузка содержит неархивные коктейли обоих статусов; структурированные данные и PDF сохраняют статус.
- Архивирование и восстановление не меняют рабочий статус.
- Все запросы остаются ограниченными текущими заведением и разрешениями сервера.
