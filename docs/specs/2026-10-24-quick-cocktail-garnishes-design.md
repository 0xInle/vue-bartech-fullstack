# Быстрые гарниры коктейля — дизайн

## Цель

Разрешить добавлять простые элементы подачи, например «Цедра апельсина», прямо при выборе гарниров коктейля. Это не должно превращать их в техкарты или менять модель сложных гарниров.

## Подтверждённое поведение

- Сложный гарнир остаётся составным продуктом с рецептурой и технологией, создаваемым в разделе «Гарниры».
- Быстрый гарнир — отдельная локальная запись заведения только с названием. Примеры: цедра, долька фрукта, ягода.
- Оба типа доступны в одном выборе гарниров коктейля и могут выбираться совместно.
- Быстрые гарниры не становятся продуктами, не имеют состава и не показываются в списке техкарт гарниров.
- Создание быстрого гарнира доступно из нижней части выпадающего списка гарниров коктейля; при сохранении вариант сразу выбирается.
- Данные быстрых гарниров изолированы по заведению. Создавать и использовать их могут только пользователи с разрешением «Управление продукцией»; сервер проверяет разрешение и область заведения.

Для хранения быстрый вариант использует локальный `ReferenceValue` типа `GARNISH`; связь с коктейлем хранится отдельно от связи с продуктом-гарниром. Создание переиспользует проверенный API локальных значений справочника.

## Подходы

1. Хранить быстрый гарнир как свободный текст в коктейле. Это не позволяет повторно использовать и централизованно выбирать один вариант; подход отклонён.
2. Создать отдельную сущность локального варианта гарнира и отдельную связь коктейля с ней, сохранив существующую связь с полноценной техкартой. Выбранный подход: он сохраняет типизацию, повторное использование и различие двух видов гарнира.
3. Ослабить требования к продукту типа «Гарнир» и сохранять быстрые варианты как продукты. Подход отклонён: он размывает модель техкарты и затрагивает поиск, архив, состав и API продукции.

## Границы реализации

- Добавить тип справочника `GARNISH`, локальную связь его значений с коктейлем и чтение объединённого списка доступных гарниров.
- Переиспользовать API создания локального значения справочника для быстрого варианта.
- Расширить сохранение и чтение коктейля для связей с обоими видами гарниров, сохраняя порядок и уникальность.
- В форме коктейля показывать составные и быстрые варианты в одном MultiSelect; в подвале селекта добавить компактное создание по аналогии с созданием локальных значений справочника.
- Отображать оба вида гарниров в карточке коктейля по названию.
- Не добавлять отдельный экран управления быстрыми гарнирами, удаление и редактирование быстрых записей в этой итерации.
- До реализации обновить `PRODUCT_MODEL.md`, `DATA_MODEL.md` и `UI_AND_NAVIGATION.md`; затем составить исполнимый план с точными файлами и статическими проверками.
