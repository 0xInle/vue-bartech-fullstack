# Личные напоминания заведения

## Цель

Добавить на главную CRM небольшой список личных задач, чтобы пользователь мог записать дело и вернуться
к нему во время работы в приложении. Это напоминания для самого пользователя, а не система постановки
задач команде.

## Согласованные правила

- Список принадлежит текущему пользователю и выбранному заведению.
- При переключении пользователя или заведения показывается соответствующий отдельный список.
- Задачи синхронизируются между устройствами и браузерами через backend.
- Другие сотрудники, даже работающие в том же заведении, личные задачи не видят.

## Предлагаемое размещение

Блок «Мои задачи» находится на главной под сводкой «Сегодня на смене» в правой колонке. Это сохраняет
поиск слева и добавляет рабочий сценарий в уже существующую область главной.

## Предлагаемый минимальный сценарий

- Добавить задачу с коротким текстом.
- Отметить задачу выполненной; выполненную задачу можно вернуть в активные.
- Удалить задачу.
- Сохранять задачи после перезагрузки страницы и повторного входа. Активные задачи не удаляются
  автоматически.
- Показывать спокойное пустое состояние, когда задач нет.

Первый вариант не включает сроки и напоминания по времени, назначение другим сотрудникам, общие задачи
заведения, повторение, комментарии, приоритеты и push-уведомления. Интерфейс не должен побуждать
пользователя постоянно держать CRM открытой.

## Подходы

1. **Личное серверное хранилище с областью пользователя и заведения — выбранный вариант.** Список
   изолирован для пользователя и заведения, синхронизируется между его устройствами и подчиняется
   серверной проверке доступа.
2. **Личное локальное хранилище браузера.** Реализуется проще, но задачи не переходят на другое
   устройство и могут потеряться при очистке данных браузера.
3. **Общий список заведения.** Все сотрудники видят и меняют одни задачи; это становится командным
   workflow, который пользователь сейчас не просит.

## Ограничения реализации

- Backend проверяет, что пользователь имеет доступ к указанному заведению; клиент не может прочитать
  или изменить чужие задачи подстановкой идентификаторов.
- Данные ограничиваются парой «пользователь + заведение».
- Перед изменением базы данных реализация включает миграцию и проходит все проверки схемы согласно
  `AGENTS.md`.
- Визуальный блок использует карточки, поля и кнопки по `UI_COMPONENT_STYLES.md`, а сценарий главной
  обновляется в `UI_AND_NAVIGATION.md`.

## Не решено этим документом

- Конкретная длина текста, лимиты количества задач и детали API остаются техническому плану.
- Способ упорядочивания списка и представление выполненных задач можно уточнить при реализации без
  изменения личной области доступа или основного сценария.
