# Выбор продукции для выгрузки и PDF перед закрытием

## Намерение

Сделать обычную выгрузку понятной: скачивать все карточки из текущего результата поиска и фильтрации, без ручного выбора чекбоксами. Удалить структурированные JSON-резервные архивы, которые пользователь не может восстановить в приложении.

## Решения и варианты

1. **Оставить резервные ZIP при закрытии.** Не соответствует решению пользователя удалить резервную выгрузку везде.
2. **Убрать все выгрузки при закрытии.** Упрощает закрытие, но лишает пользователя возможности сохранить техкарты.
3. **Оставить только PDF.** Выбранный вариант: удалить JSON и манифесты; при закрытии заведения оставить пакет PDF выбранных карточек, а при закрытии компании формировать один ZIP с PDF по всем доступным пользователю заведениям.

## Поведение основной страницы

- Одна кнопка «Выгрузить продукцию» формирует архив всего текущего результата поиска и фильтрации. При отсутствии условий поиска и фильтров он включает всю доступную продукцию, в том числе архивную при наличии соответствующего разрешения.
- Отдельный выбор карточек на странице отсутствует. Для выгрузки одной карточки пользователь использует действие в её карточке.
- В обычном потоке больше нет кнопки и API-действия структурированной резервной выгрузки.

## Закрытие заведения и компании

- Закрытие заведения сохраняет PDF одной карточки и ZIP отмеченных PDF; действие резервного ZIP удаляется.
- Закрытие компании предлагает PDF-only ZIP по всем заведениям, доступным инициатору. Состав области вычисляет и проверяет backend; клиент не передаёт произвольную область.
- Возможность явно продолжить закрытие без выгрузки сохраняется.

## Ограничения и не-цели

- Backend остаётся источником разрешений, области и допустимых архивных карточек.
- Обратный импорт не добавляется. JSON-данные, продуктовые снимки и манифесты в выгрузку не входят.
- Пользовательская история файлов, новые права и изменение сроков хранения не входят в работу.
- Существующие изменения пользователя, включая `.gitignore`, сохраняются.

## Проверка результата

- Документация интерфейса и спецификация этапа 8 отражают новый пользовательский сценарий.
- API контракт и типы выгрузки соответствуют PDF-only вариантам.
- Проверяются ESLint и форматирование затронутых файлов. Тесты, typecheck, сервер, браузер и визуальная проверка не запускаются без отдельной просьбы.
