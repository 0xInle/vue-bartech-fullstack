# Последние изменения на главной

## Цель

Добавить в правую колонку главной компактный блок с пятью последними действиями из журнала, чтобы
барменеджер видел недавнюю активность, не переходя в раздел истории.

## Согласованное поведение

- Блок «Последние изменения» размещается под блоком личных задач.
- Показываются до трёх записей в порядке от новых к старым: краткое действие, дата и автор.
- Используется текущий API истории. Backend продолжает ограничивать выдачу выбранным рабочим
  пространством и правами пользователя: без `view_history` доступны только предусмотренные моделью
  собственные события; полную историю видят пользователи с соответствующим правом.
- Отдельный API и новые права не добавляются. В интерфейсе не показываются подробности событий.
- Загрузка, ошибка и пустое состояние отображаются внутри блока.

## Подходы

- **Переиспользовать API истории** — сохраняет текущий серверный scope и безопасные резюме событий;
  выбранный подход.
- **Добавить отдельный endpoint для главной** — дублирует запрос и правила доступа без новой
  потребности продукта, поэтому не используется.

## Оформление

Компактный список следует стилю карточек «Сегодня на смене» и «Мои задачи»: общий заголовок уровня
секции, нейтральный контейнер и небольшие строки.
