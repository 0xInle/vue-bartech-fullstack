# Удаление архивного продукта: план реализации

> **Для исполнителя:** выполняй задачи по порядку и отмечай пункты чекбоксами.

**Цель:** исключить удаление активных продуктов при безвозвратном удалении архивной карточки и
показывать для архивного продукта только понятный сценарий удаления.

**Архитектура:** backend повторно проверяет статусы всей зависимой цепочки под транзакционной
блокировкой и отклоняет удаление, если в ней есть активные потомки. Общая модалка удаления выбирает
режим по статусу корневой карточки: активный продукт сохраняет текущие режимы, архивный показывает
только удаление архивной цепочки либо блокирующее сообщение.

**Стек:** NestJS, TypeScript, Vue 3, PrimeVue, Nuxt.

**Спецификация:** `docs/superpowers/specs/2026-11-03-archived-product-delete-design.md`.

## Общие ограничения

- Сервер остаётся источником полномочий, статусов, зависимостей и допустимых операций.
- Архивные карточки доступны только для чтения; из модалки удаления для них нельзя выполнять замену.
- Активные продукты не удаляются и не архивируются автоматически при удалении архивного корня.
- Если зависимостей нет, сохраняется короткое подтверждение одиночного удаления.
- Не добавлять тесты; не запускать тесты, typecheck, сервер, браузер или визуальную проверку.
- Форматировать только затронутые файлы Prettier; сохранять все существующие изменения.

## Области изменений

- `packages/backend-products/src/archive/archive-mutation.service.ts` — транзакционная проверка активных
  потомков архивного корня до удаления.
- `apps/web/app/features/archive/components/PermanentDeleteActionButton.vue` — единственный режим
  удаления архивной цепочки без дублирующей сводки и блокирующий список активных зависимостей;
  поддержка текстового варианта кнопки для архивного Drawer.
- `apps/web/app/features/archive/components/ArchiveProductDrawer.vue` — две текстовые кнопки действий
  с зелёным и красным оформлением.
- `apps/backend/src/products/archive-problem-details.ts`, `apps/backend/src/products/archive.dto.ts` и
  `apps/web/app/features/archive/composables/useProductArchive.ts` — только если понадобится отдельный
  тип конфликта; предпочесть уже поддерживаемый конфликт зависимостей с актуальным планом.
- `PRODUCT_MODEL.md` и `UI_AND_NAVIGATION.md` — правила статусов цепочки при удалении архивного корня и
  сценарий модалки.

## Порядок работы

### Задача 1. Защитить архивную цепочку на сервере

- [ ] Перед изменением повторно проверить `git status` и текущую обработку безвозвратного удаления.
- [ ] В `ArchiveMutationService` после блокировки заведения и пересчёта плана, до удаления связей,
      проверить случай `plan.root.status === "ARCHIVED"`.
- [ ] Если `plan.deleteChain` содержит хотя бы один продукт со статусом `ACTIVE` кроме корня,
      отклонить операцию без побочных эффектов и вернуть поддерживаемый конфликт с актуальным планом и
      сообщением о необходимости архивировать перечисленные продукты отдельно.
- [ ] Для архивного корня удалить только цепочку, в которой все потомки имеют статус `ARCHIVED`;
      активный корень оставить в прежнем сценарии без изменений.

### Задача 2. Развести режимы модалки по статусу корня

- [ ] В `PermanentDeleteActionButton.vue` определить архивный корень по `plan.root.status`.
- [ ] Для архивного корня скрыть кнопку и контролы замены; при отсутствии зависимостей оставить короткое
      подтверждение без изменений.
- [ ] При наличии зависимостей и отсутствии активных потомков сразу показать единственный сценарий:
      точное название и подтверждение удаления цепочки без отдельной сводки количества.
- [ ] Если в цепочке есть активные потомки, не показывать замену и не разрешать подтверждение; вывести
      русскоязычное сообщение с названиями и типами активных карточек и просьбой архивировать их отдельно.
- [ ] Сохранить повторную серверную проверку плана, защиту от повторного подтверждения устаревшего плана,
      разрешения и поведение удаления активного корня.

### Задача 3. Синхронизировать документацию и выполнить статические проверки

- [ ] Обновить `PRODUCT_MODEL.md`: удаление архивного корня не удаляет активные зависимые карточки;
      при их наличии действие блокируется.
- [ ] Обновить `UI_AND_NAVIGATION.md`: архивный корень не предлагает замену и не дублирует количество
      удаления; активные потомки требуют отдельной архивации; описать кнопки Drawer.
- [ ] Форматировать только затронутые файлы через `pnpm exec prettier --write <пути>`.
- [ ] Выполнить `git diff --check` и доступные backend/web сборки; не запускать запрещённые проверки.

## Основные риски для ручного просмотра

- Активный потомок на любой глубине цепочки: сервер блокирует удаление и UI показывает его, хотя таблица
  прямых связей может его не содержать.
- Граф изменился между показом плана и подтверждением: ничего не удаляется, отображается свежий план.
- Архивный корень без зависимостей: не появляется лишнее поле точного названия.
- Архивный корень с одними архивными зависимостями: предлагается одна операция удаления без замены.
- Удаление активного корня: существующие режимы и ограничения остаются прежними.
