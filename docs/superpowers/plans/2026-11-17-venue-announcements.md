# План реализации объявлений заведения

> **Для исполнителей:** использовать `superpowers:executing-plans` и выполнять задачи последовательно. Не создавать и не запускать тесты без отдельного разрешения.

**Цель:** сотрудники видят общие объявления текущего заведения на Главной; пользователи с `manage_venue` могут их создавать, изменять и удалять.

**Архитектура:** завести отдельную сущность и backend-пакет по образцу личных напоминаний, но с venue-wide чтением и серверной проверкой `manage_venue` на мутациях. API-клиент генерируется из Nest OpenAPI; Vue Query composable связывает API с блоком Главной и Dialog создания/редактирования.

**Технологии:** Nuxt 4, Vue 3, PrimeVue 4, TanStack Vue Query, NestJS, Prisma 7, PostgreSQL.

**Спецификация:** `docs/superpowers/specs/2026-11-17-venue-announcements-design.md`

## Ограничения

- Backend остаётся единственным источником полномочий и принадлежности к заведению.
- `manage_venue` требуется для создания, изменения и удаления; чтение доступно участнику выбранного рабочего пространства.
- Каждая схема Prisma сопровождается миграцией; схема проверяется, Prisma Client генерируется, ожидающие миграции применяются локально, затем `prisma migrate status` должен подтвердить актуальность.
- Не создавать или запускать unit-, integration- и e2e-тесты; не запускать `typecheck`.
- Форматировать только изменённые файлы Prettier; разрешены ESLint, Prisma validate/generate, API generation и build.
- Не запускать браузер и сервер для визуальной проверки; пользователь проверит интерфейс самостоятельно.

## Проверка перед ревью

- Объявления читаются только внутри выбранного рабочего пространства.
- Запросы без `manage_venue` не могут создавать, менять или удалять объявления даже при прямом API вызове.
- Данные другого заведения невозможно прочитать или изменить через подмену ID.
- Публикация сразу появляется первой, изменение отражается в списке, удаление требует подтверждения и убирает карточку.
- Заголовок и текст проходят серверную и клиентскую проверку на длины 1–100 и 1–1000 символов.
- Обновлены MVP_SCOPE, DATA_MODEL, ROLES_AND_PERMISSIONS и UI_AND_NAVIGATION.

## Области особого внимания

- Членство в рабочем пространстве прекращено между загрузкой страницы и API-запросом.
- Мутация с `manage_venue`, снятым после загрузки интерфейса.
- Валидные UUID чужой компании/заведения и ID объявления другого заведения.
- Параллельные изменения одной записи и обновление списка после мутации.
- Длинные заголовки/текст и узкий viewport; проверка визуально остаётся за пользователем.
