# Личные напоминания заведения — план реализации

> **Для исполнителя:** выполнить шаги по порядку. Существующие пользовательские изменения сохранить.

**Цель:** добавить в главную CRM личный синхронизируемый список напоминаний для выбранного заведения.

**Архитектура:** хранить задачи в PostgreSQL с привязкой к пользователю и заведению. Backend получает
владельца только из сессии и проверяет доступ к заведению; клиент использует API через сгенерированный
клиент. На главной список располагается под сводкой смены.

**Стек:** Nuxt 4, Vue 3, TypeScript, TanStack Vue Query, PrimeVue 4, NestJS, Prisma, PostgreSQL.

**Спецификация:** `docs/superpowers/specs/2026-11-17-venue-personal-reminders-design.md`

## Общие ограничения

- Область данных — текущий пользователь и текущее заведение; коллеги не видят личные задачи.
- Проверка принадлежности пользователя заведению выполняется на backend при каждом запросе.
- При переключении заведения запрашивается его отдельный список; не показывать данные из предыдущего
  контекста даже на время загрузки.
- Поддержать добавление текста, отметку выполнения и возврат в активное состояние, удаление; не добавлять
  сроки, назначения, повторы и уведомления.
- Следовать `UI_COMPONENT_STYLES.md` и сценарию главной в `UI_AND_NAVIGATION.md`.
- Не создавать тестовые файлы, тестовую инфраструктуру или зависимости и не запускать тесты.
- Не запускать `typecheck`, локальный сервер или браузер. Визуальную проверку оставляет пользователю.
- Любое изменение Prisma-схемы включает миграцию, `prisma validate`, генерацию клиента, применение
  миграции к локальной базе и успешный `prisma migrate status`.

## Области изменений

- `MVP_SCOPE.md`, `DATA_MODEL.md`, `UI_AND_NAVIGATION.md` — включить личные напоминания в состав MVP,
  концептуальную модель и сценарий главной.
- `packages/database/prisma/reminders.prisma`, `identity.prisma`, `organizations.prisma` и новая
  миграция — модель, связи владельца/заведения и каскадные ограничения.
- Новый пакет `packages/backend-reminders/` — выборка и операции над задачами с фильтрацией по владельцу
  и заведению.
- `apps/backend/src/reminders/` и `apps/backend/src/app.module.ts` — REST-контроллер, DTO и регистрация
  модуля; использовать существующие сессию, `CurrentUser` и `OrganizationsService.findWorkspaceForUser`.
- `packages/api-client/openapi.json`, `packages/api-client/src/generated/` — результат штатной генерации API.
- Новые `apps/web/app/features/workspace/composables/useVenueReminders.ts` и
  `apps/web/app/features/workspace/components/MyVenueReminders.vue`, плюс
  `VenueHomeScreen.vue` — запросы/мутации, состояния блока и размещение.

## На что обратить внимание при ревью

- Подстановка чужого `userId` или `venueId` не позволяет прочитать, изменить или удалить задачу другого
  пользователя либо заведения. Проверку доступа выполнить для всех методов.
- После смены рабочего пространства старый список не отображается; query key включает компанию,
  заведение и пользователя, а кэш очищается/разделяется корректно.
- Выполненные задачи остаются доступными для возврата в активные до явного удаления.
- Ошибка или пустое состояние блока не скрывает поиск и сводку смены.
- Быстрые повторные нажатия не создают дубли из одной операции, а состояние мутации отражено в интерфейсе.
