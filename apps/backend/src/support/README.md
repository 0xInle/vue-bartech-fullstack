# API обращений в поддержку

Контроллеры публикуют собственные обращения в `/support/requests` и внутреннюю очередь в
`/internal/support`. Пользовательский API требует клиентскую сессию и фильтрует данные по автору;
внутренний API требует отдельную `InternalUser`-сессию и разрешение `support_requests`.

До пяти вложений принимаются в одном multipart upload, сохраняются приватно в карантин и
получают метаданные вместе с outbox-записями в одной транзакции. Временная ссылка на конкретный
файл выдаётся только после чистого результата ClamAV и повторной проверки авторства или
внутреннего разрешения.

API использует `@bartech/backend-support`; описание бизнес-границ находится в спецификации среза.

`support.controller.ts` также обслуживает чтение/отправку сообщений и раздельные курсоры прочтения.
Структурированный запрос доступа создаёт внутренняя сторона диалога; клиент подтверждает его через
`service-access.controller.ts`. Пользователь и сотрудник очереди могут отозвать grant; отзыв
завершает связанные служебные сессии и журналируется. Закрытие обращения при активном grant
отклоняется backend, закрытие не отзывает доступ автоматически. Внутренние продуктовые действия
требуют `service_access`, действующую `ServiceSession` и повторную проверку области.
