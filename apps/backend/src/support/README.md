# API обращений в поддержку

Контроллеры публикуют собственные обращения в `/support/requests` и внутреннюю очередь в
`/internal/support`. Пользовательский API требует клиентскую сессию и фильтрует данные по автору;
внутренний API требует отдельную `InternalUser`-сессию и разрешение `support_requests`.

Вложение принимается как ограниченный multipart upload, сохраняется приватно в карантин и
получает метаданные вместе с outbox-записью в одной транзакции. Временная ссылка выдаётся только
после чистого результата ClamAV и повторной проверки авторства или внутреннего разрешения.

API использует `@bartech/backend-support`; описание бизнес-границ находится в спецификации среза.

`service-access.controller.ts` предоставляет отдельные команды выдачи и отзыва grant. Внутренние
команды требуют `service_access`; продуктовые действия проходят через отдельный controller с
действующей `ServiceSession` и повторной проверкой области.
