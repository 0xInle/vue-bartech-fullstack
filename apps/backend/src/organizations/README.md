# HTTP API рабочего контекста

Модуль `organizations` предоставляет HTTP-контракт рабочего контекста и команды заведений. Контроллеры связывают DTO с сервисами и не содержат предметных правил.

`OrganizationsController` принимает/возвращает DTO и связывает HTTP-запрос с прикладными сервисами. `WorkspacePermissionGuard` требует валидную сессию, разрешает компанию и заведение только через доступную пользователю read-модель и проверяет обязательное разрешение из метаданных endpoint. Идентификаторы из URL не считаются полномочием; если контекст не найден или недоступен, клиент получает одинаковый ответ.

`InvitationsController` предоставляет локальные маршруты команды заведения и маршруты команды шеф-барменов компании. Для локальных операций контекст и эффективные разрешения проверяет `WorkspacePermissionGuard`; полномочия компании повторно проверяет `OrganizationsService`, поэтому идентификатор компании из URL не является доказательством доступа. Публичные маршруты приглашения не требуют аккаунта до принятия; подтверждённая почта и действующая 60-минутная сессия обязательны до создания постоянного членства. `IdentityService` связывает создание/закрытие приглашения с Outbox, а назначение локальной роли или роли уровня компании выполняет атомарно.

`OrganizationLifecycleService` подготавливает операцию закрытия, проверяет право инициатора создать
привязанную выгрузку, атомарно закрывает заведение или запускает 168-часовое ожидание компании и
разрешает его отмену уполномоченному участнику. Закрытие заведения с выбранной выгрузкой возможно
только после её готовности; явный путь без файла не создаёт исключения скачивания. Worker перед
удалением компании оставляет только связанный готовый и неистёкший файл. Отдельный защищённый маршрут
возвращает инициатору ссылку только на файл собственной закрытой операции и не восстанавливает
доступ к рабочей области. Незавершённые и обычные запросы проходят идемпотентную очистку.

Модель членств и вычисление прав принадлежат `packages/backend-organizations`, а сессия и текущий пользователь — `packages/backend-identity`. Изменение ролей, удаление сотрудников и передача управления остаются отдельными срезами этапа 4.
