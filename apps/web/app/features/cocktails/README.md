# Коктейли

Модуль `cocktails` реализует первый законченный сценарий технологических карт текущего заведения:
список, прямое открытие карточки, создание и редактирование коктейля. Страницы Nuxt остаются тонкими контейнерами и
подключают только соответствующий экран feature-модуля.

## Границы

- `components/CocktailListScreen.vue` — список, локальный поиск и открытие Drawer создания.
- `components/CocktailCardScreen.vue` — карточка по постоянному URL, действие редактирования для
  пользователя с `manage_products` и обновление карточки после сохранения.
- `components/CocktailFormDrawer.vue` — единая форма создания и редактирования. Явный режим
  определяет начальные значения, заголовок и мутацию, но не дублирует разметку, валидацию или
  строки состава. При ошибке форма остаётся открытой, а введённые значения не теряются.
- `components/CocktailComponentRows.vue` — динамические строки состава. Он использует
  `features/products/IngredientSelector.vue`, но не выполняет сохранение коктейля.
- `components/LocalIngredientCreateForm.vue` — вложенное создание временного локального ингредиента
  из одной строки состава; самостоятельного маршрута или экрана каталога нет.
- `composables/useCocktails.ts` — запросы списка, карточки, гарниров и справочников, а также
  операции создания и изменения. Ключи TanStack Query: `cocktail-list`, `cocktail-card`,
  `cocktail-garnishes` и `product-references`; в них входят компания и заведение.

Кнопки создания и редактирования доступны только при `manage_products`, однако окончательная
проверка прав и области данных выполняется backend. Список, карточка и гарниры возвращаются только
для текущего `venueId`. Редактирование заготовок и гарниров, включая предупреждения о зависимых
активных продуктах, не входит в этот срез.

При изменении HTTP-контракта сначала меняются DTO и контроллер backend, затем запускается штатная
команда `pnpm api:generate`. Файлы в `packages/api-client/src/generated` вручную не редактируются.
