# Учётная запись и аутентификация

Срез `identity` отвечает за вход и выход пользователя, текущую серверную сессию, CSRF-токен, восстановление пароля и отображение данных учётной записи в профиле. Он не создаёт компании и не управляет заведениями.

`useIdentityFlow` загружает сессию, различает авторизованное состояние, отсутствие авторизации и ошибку запроса, а также выполняет запросы к API идентификации и хранит состояние учётной записи. `LoginForm` и `PasswordRecoveryForm` отображают публичные формы. `AccountProfileDrawer` открывается из кнопки профиля в рабочем пространстве и на авторизованном лендинге; на лендинге он также содержит удаление аккаунта, чтобы действие оставалось доступным после выхода из всех рабочих пространств. Если членства ещё есть, из предупреждения можно перейти к выбору рабочих пространств. Для ожидания удаления используется `AccountDeletionPendingPanel`: в этом ограниченном состоянии доступны только отмена удаления, выход и восстановление пароля. В профильном Drawer доступны изменение имени и основного email, смена пароля, завершение сеансов и установка PWA. Предложение установки показывается только при поддержке браузера; правила установки описаны в `features/pwa/README.md`. Другие срезы используют состояние сессии через этот composable, не вызывая session API самостоятельно.

Ответ API текущей сессии содержит только доступные пользователю рабочие пространства и рассчитанные backend разрешения. Подробный список устройств/сессий не входит в MVP; доступны выход на текущем устройстве и выход на всех устройствах.

Общие типы пользователя и доступных рабочих пространств находятся в `app/types/user-workspaces.ts`, чтобы соседние срезы не импортировали модели друг у друга.

На лендинге формы входа и регистрации изначально скрыты. Вход открывается кнопкой в шапке, а регистрация — кнопкой под главным слоганом; повторное нажатие на активную кнопку закрывает форму, другая кнопка переключает режим. В форме входа нет ссылки на регистрацию. Восстановление начинается вводом email и отдельной кнопкой, а возврат ко входу выполняется центрированной кнопкой; подтверждение кодом и установка нового пароля сохраняются отдельным следующим шагом.

После успешного входа координатор обновляет сессию и передаёт навигацию к первому доступному заведению срезу `organizations`. Профиль не имеет отдельного маршрута: это общий аккаунтный Drawer в рабочем пространстве и на авторизованном лендинге; удаление аккаунта доступно только из лендинга.

Серверные правила, полномочия и жизненный цикл учётной записи определяются backend и `AUTHENTICATION_FLOW.md`.
