# История действий

Feature `history` показывает доступные пользователю события рабочего пространства. Маршрут
`/history` остаётся тонким контейнером: он получает рабочий контекст и подключает `HistoryScreen`.

`useAuditHistory` обращается к сгенерированному API-клиенту с ключами TanStack Query, содержащими
компанию, заведение и фильтры. События загружаются постранично, варианты автора отдельно
запрашиваются у защищённого endpoint из доступных пользователю событий; roster команды и уже
загруженные страницы истории как источник вариантов не используются. Удалённые/недоступные авторы
не появляются в фильтре, а устаревший выбранный автор очищается после успешного ответа. Экран
отражает фильтры и карточку в URL, показывает автора,
действие, время и название сущности, а курсор открывает следующую страницу. Набор типов событий
переводится в короткие русские подписи; неизвестный тип отображается нейтрально.

Ссылка из карточки коктейля, заготовки или гарнира ведёт в этот же список с `entityType` и
`entityId`. Видимость пункта навигации служит подсказкой; фактический scope каждый раз проверяет
backend. Правила доступа и состав событий находятся в
[`docs/specs/2026-10-15-stage-8-audit-history.md`](../../../../../docs/specs/2026-10-15-stage-8-audit-history.md).
