# Рабочее пространство

Срез `workspace` показывает CRM-каркас текущего заведения и профиль. Он получает компанию, заведение, роль и эффективные разрешения из серверного API; URL определяет выбранный контекст, но сам по себе не даёт доступа.

`useVenueWorkspace` загружает сессию через `identity`, а данные выбранного контекста запрашивает отдельным Orval-клиентом. Backend проверяет членство и возвращает одинаковый ответ для отсутствующего и недоступного заведения. При отсутствии сессии пользователь возвращается на публичный экран.

`WorkspaceShell` отображает текущие компанию и заведение, переключатель рабочих пространств и адаптивную навигацию. На широком экране используется постоянная левая панель: рабочие маршруты находятся в основном списке, профиль — в нижней части. На телефоне верхняя панель показывает контекст, а доступная навигация расположена снизу. Главная, профиль, команда, история, шеф-бармены компании и создание заведения показываются только на существующих маршрутах и согласно разрешениям. `VenueHomeScreen` и `WorkspaceProfileScreen` собирают оболочку с содержимым экрана. Маршруты Nuxt остаются тонкими точками входа.

`CompanyClosureBanner` внутри оболочки рабочего пространства показывает режим только для чтения и
срок закрытия компании. Возможность отмены приходит с сервера для конкретного пользователя.

Профиль показывает имя, email, доступные рабочие пространства, должности и рассчитанные сервером права. Управление сессией ограничено выходом на текущем устройстве или на всех устройствах; списка устройств и выборочного отзыва нет.

Нейтральные типы пользователя и рабочих пространств находятся в `app/types/user-workspaces.ts`, чтобы не создавать зависимость между срезами `identity` и `workspace`. Полные правила ролей определены в `ROLES_AND_PERMISSIONS.md`, а технические границы — в `ARCHITECTURE.md`.
