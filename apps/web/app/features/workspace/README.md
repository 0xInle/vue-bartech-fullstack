# Рабочее пространство

Срез `workspace` показывает CRM-каркас текущего заведения и профиль. Он получает компанию, заведение, роль и эффективные разрешения из серверного API; URL определяет выбранный контекст, но сам по себе не даёт доступа.

`useVenueWorkspace` загружает сессию через `identity`, а данные выбранного контекста запрашивает отдельным Orval-клиентом. Backend проверяет членство и возвращает одинаковый ответ для отсутствующего и недоступного заведения. При отсутствии сессии пользователь возвращается на публичный экран.

`WorkspaceShell` отображает компанию, выбранное заведение, адаптивную навигацию и профиль. На широком экране постоянная левая панель группирует ссылки через PrimeVue `PanelMenu`; группы «Каталог», «Команда» и «Управление» раскрыты при первом отображении. Состояние групп сохраняется между страницами текущего заведения; пользователь может сворачивать и раскрывать их вручную. В группе «Команда» ссылки на отдельное управление и график показываются независимо по доступным разрешениям и в установленном порядке. Стрелки групп размещены справа и уменьшены; заголовки групп используют ту же типографику, что и ссылки. На телефоне быстрые ссылки остаются снизу, а дополнительные разделы находятся в PrimeVue `Drawer`. Пункты меню формируются по серверным разрешениям текущего контекста.

`WorkspaceIdentity` показывает название компании и выбранное заведение. При нескольких заведениях заведение отображается кнопкой; по нажатию поверх содержимого открывается popup PrimeVue `Menu` со списком доступных заведений. Названия пунктов выровнены по центру и имеют размер `text-xs`; текущее заведение выделено основным зелёным цветом без иконки. Выбор другого переключает рабочее пространство и закрывает меню. Если заведение одно, оно отображается текстом. Имя с фамилией показывается отдельно, если это предусмотрено расположением компонента. В desktop-панели и мобильном Drawer `WorkspaceActionBar` показывает
иконки профиля, темы и справочного центра. Управление заведениями перенесено на авторизованный
аккаунтный лендинг в срез `organizations`; выход из аккаунта остаётся в профиле. Повторную проверку
прав для операций с заведениями выполняет backend.
В мобильном режиме переключение контекста закрывает Drawer, нижняя навигация не меняется.

`VenueHomeScreen` размещает поиск продукции; из остальных рабочих экранов он открывается кнопкой в
верхней части содержимого, на мобильном — полноэкранной боковой панелью. Маршруты Nuxt остаются
тонкими точками входа.

На главной `TodayShiftRoster` показывает состав текущей смены, `MyVenueReminders` — личные задачи
пользователя в выбранном заведении, а `RecentAuditEvents` — три последние доступные записи журнала.
`useVenueReminders` загружает и изменяет задачи через API; сервер ограничивает операции текущим
пользователем и рабочим пространством. Задачи синхронизируются через backend, отмеченные выполненными
остаются в списке до удаления. Последние записи запрашиваются через защищённый API истории с теми же
проверками пользователя, области и разрешений, что и на странице истории.

`TeamAnnouncements` показывает общий список объявлений выбранного заведения. Список и мутации
загружаются через `useVenueAnnouncements`; сервер ограничивает область текущим заведением, а
создание, изменение и удаление дополнительно защищены эффективным правом `manage_venue`. Форма
создания и редактирования находится в `TeamAnnouncementDialog`.

`VenueChecklists` показывает названия общих инструкций текущего заведения. Выбор названия открывает
`VenueChecklistViewDialog` с упорядоченными пунктами; управление доступно пользователям с
`manage_venue` через `VenueChecklistEditorDialog`. `useVenueChecklists` загружает и изменяет данные
через защищённый API с ключом запроса, ограниченным пользователем и текущим рабочим пространством.

`CompanyClosureBanner` внутри оболочки рабочего пространства показывает режим только для чтения и
срок закрытия компании. Возможность отмены приходит с сервера для конкретного пользователя.

Профиль показывает имя, email, доступные рабочие пространства, должности и рассчитанные сервером права. Управление сессией ограничено выходом на текущем устройстве или на всех устройствах; списка устройств и выборочного отзыва нет.

Нейтральные типы пользователя и рабочих пространств находятся в `app/types/user-workspaces.ts`, чтобы не создавать зависимость между срезами `identity` и `workspace`. Полные правила ролей определены в `ROLES_AND_PERMISSIONS.md`, а технические границы — в `ARCHITECTURE.md`.

`WorkspaceShell` содержит межраздельный Drawer карточки продукции для просмотра связей из модалки
удаления. Он открывается поверх текущей страницы и закрывается без навигации, сохраняя исходную
модалку и её состояние.
