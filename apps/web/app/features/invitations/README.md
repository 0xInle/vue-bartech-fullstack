# Принятие приглашения

Публичный срез `/invitations` показывает минимальные данные приглашения в существующее заведение, на роль шеф-бармена либо на создание нового заведения в компании с ролью бар-менеджера. Для приглашения шеф-бармена показываются компания и пояснение о доступе ко всем её заведениям. Для нового заведения приглашённый указывает название в последнем шаге. Ссылка содержит токен во fragment (`/invitations#<token>`): клиент сразу удаляет fragment из адресной строки, держит токен только в памяти до принятия или отклонения и передаёт его API только в теле POST-запросов. Ссылка сама по себе не создаёт аккаунт или членство; принятие открывает привязанную к браузеру HttpOnly-сессию на 60 минут.

После принятия обновление страницы восстанавливает поток по HttpOnly-cookie без повторной передачи токена приглашения. Если страницу обновили до принятия, пользователь повторно открывает ссылку из письма.

`useInvitationAcceptance` координирует API-вызовы, а `InvitationAcceptanceScreen` отображает шаги. Для нового пользователя аккаунт, назначенная роль и рабочая сессия создаются одной серверной транзакцией после подтверждения email. Для существующего аккаунта backend проверяет совпадение подтверждённого email и совместимость роли. При приглашении в заведение создаётся локальное членство; при приглашении шеф-бармена назначается роль уровня компании без локальной роли, после чего пользователь получает доступ ко всем её заведениям.

Постоянные правила приглашений находятся в `REGISTRATION_FLOW.md`; серверная схема описана в `DATA_MODEL.md`.
