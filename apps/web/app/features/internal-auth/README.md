# Внутренняя аутентификация

Срез `internal-auth` обслуживает только отдельный вход сотрудников IndieBar на `/internal`. Он
координирует пароль, TOTP, первичную настройку, восстановление по recovery-коду и управление
собственными внутренними сессиями. Клиентское состояние аккаунта и рабочие данные сюда не входят.

`InternalAuthScreen` отображает состояния потока, а `useInternalAuth` вызывает отдельный API,
удерживает challenge и временные секреты только в памяти страницы и загружает текущую внутреннюю
сессию. Страница `/internal` остаётся тонкой точкой композиции.

Требования к MFA и восстановлению зафиксированы в
`docs/specs/2026-10-16-stage-9-internal-user-authentication-design.md`. Backend является источником
состояния и полномочий; документация API и серверная защита размещены в `backend-identity`.
