# Компании и заведения

Срез `organizations` отвечает за показ доступных пользователю заведений и переход в выбранное рабочее пространство. Он не отвечает за регистрацию нового аккаунта и не владеет аутентификацией.

`useOrganizations` предоставляет рабочие пространства и компании без заведений из текущей сессии. После входа открывается первое доступное заведение, а если рабочих пространств нет — компания без заведений. `OrganizationsPanel` показывает доступные пользователю заведения и ссылку «Добавить заведение» для пустой компании шеф-бармена; доступ к действиям дополнительно проверяет backend. Отображение аккаунта и выход принадлежат срезу `identity`.

Типы пользователя и рабочих пространств импортируются из нейтрального `app/types/user-workspaces.ts`, а не из среза `identity`.

Создание первой и дополнительной компании остаётся отдельным публичным сценарием «Создать компанию» и не удаляется из продукта. Организационные бизнес-правила определяются `COMPANY_AND_VENUE_LIFECYCLE.md` и `MVP_SCOPE.md`.

`OrganizationLifecyclePanel` подготавливает операцию закрытия и показывает выгрузки, созданные
только в её контексте. Закрытие заведения ждёт готовности выбранного файла либо требует явный выбор
продолжить без него. Для единственного локального бармена/старшего бармена панель отдельно
показывает атомарное действие «Покинуть и закрыть заведение» на основании защищённой серверной
проверки состава. При закрытии компании шеф-бармен может сформировать общий ZIP до начала ожидания и
из плашки в течение 168 часов. `CompanyClosureBanner` показывает точный дедлайн и действие отмены;
страница операции закрытия остаётся отдельным маршрутом и после удаления области. Все полномочия и
переходы состояния повторно проверяет backend.

`EmptyCompanyPageScreen` открывает приглашения бар-менеджера из контекста пустой компании без привязки к `venueId` и `WorkspaceShell`. `useCompanyVenueInvitations` загружает список, создаёт приглашение и отзывает его через API; отправитель указывает только email. Имя заведения вводит приглашённый при завершении принятия ссылки, поэтому до этого шага постоянное заведение не создаётся. Полномочия и ограничения повторно проверяет backend. Пользовательский порядок приглашения описан в `REGISTRATION_FLOW.md`.

`VenueManagementPageScreen` собирает оболочку и экран управления заведениями. `useVenueManagement`
показывает только доступные текущему пользователю заведения компании и вызывает защищённое создание
нового заведения. `VenueManagementScreen` объединяет создание, существующий сценарий приглашения и
действия закрытия. `OrganizationLifecyclePanel` получает явный контекст целевого заведения; сервер
повторно проверяет полномочия при закрытии. Подробный интерфейс описан в `UI_AND_NAVIGATION.md`.
