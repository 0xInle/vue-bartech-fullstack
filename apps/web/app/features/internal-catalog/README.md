# Внутреннее управление каталогом

Feature предоставляет внутренней команде IndieBar очередь неоднозначных локальных ингредиентов и
управление существующими глобальными карточками. Доступ включается только после загрузки
`InternalUser`-сессии с разрешением `global_catalog`.

Экран показывает поля локального ингредиента и основание сопоставления без названий клиента,
заведения и содержимого рецептур. Сотрудник может связать позицию с найденным активным глобальным
ингредиентом, создать глобальную карточку или оставить ингредиент локальным. Все изменения проходят
через защищённый внутренний API; экран подтверждает операции и сбрасывает выбранную карточку после
успеха. Query keys каталога включают страницу или поисковый запрос.

При связывании и создании backend атомарно заменяет ссылки только в исходном заведении, включая
архивную продукцию, и записывает аудит. При решении оставить локальным backend закрывает кандидата;
неизменённая карточка не возвращается в очередь до следующего изменения. Правила данных описаны в
`DATA_MODEL.md`, а состав backoffice MVP — в `MVP_SCOPE.md`.

Экран `/internal/catalog/manage` использует `useInternalCatalogManagement` для поиска и карточки
глобального ингредиента, редактирования полей и действий с алиасами. Неподтверждённые алиасы явно
отличаются от подтверждённых. Слияние сначала загружает серверный предварительный просмотр, затем
передаёт обе версии `updatedAt` в подтверждение; при конфликте версии нужно получить новый preview.
Backend сообщает только глобальные карточки, алиасы и число ссылок, не возвращая клиентские рецептуры.

Экран `/internal/catalog/categories` и `useInternalCatalogCategories` управляют системными
категориями ингредиентов. Дерево показывает активные и неактивные узлы; для каждого доступны создание,
переименование, смена родителя для допустимых узлов, изменение порядка и активация. Маршрут сначала
проверяет внутреннюю сессию и `global_catalog`, затем загружает дерево. Неактивная категория остаётся
видимой в уже назначенной карточке и может быть сохранена без смены; формы создания и выбора новой
категории используют только активные значения.
