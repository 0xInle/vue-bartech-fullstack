# Заготовки

Модуль `preparations` реализует сценарий работы с заготовками текущего заведения: адаптивный
список, карточку в Drawer, создание и редактирование в Drawer. Страницы Nuxt остаются
тонкими контейнерами и подключают только экраны feature-модуля.

## Границы

Рабочий статус заготовки («Активен» / «Проработка») хранится отдельно от архива. Новые записи по
умолчанию получают статус «Проработка», миграция назначает существующим статус «Активен». Фильтр
статуса пустой по умолчанию; архивирование и восстановление остаются отдельным сценарием.

- `PreparationListScreen.vue` отвечает за адаптивный список, URL-состояние, фильтры, архивирование и открытие карточки.
- `PreparationCardDrawer.vue` показывает техкарту поверх списка и предоставляет действия по текущим разрешениям.
  В межраздельном просмотре связи из модалки удаления `readOnly` скрывает редактирование; обычное
  открытие из списка и по прямому URL сохраняет прежнее поведение.
- `PreparationCardScreen.vue` — адаптер старого маршрута с ID; он передаёт выбранную карточку списку.
- `PreparationFormDrawer.vue` координирует создание и редактирование, валидацию и обработку ошибок сохранения.
  Шапка и footer с кнопками «Отмена» / «Сохранить» закреплены; прокручивается только область полей.
- `PreparationCategorySelect.vue` показывает системные и локальные категории текущего заведения и создаёт локальное значение через защищённый API.
- `PreparationImpactDialog.vue` показывает названия и типы активной продукции, затронутой изменением заготовки.
- `PreparationComponentRows.vue` редактирует только строки состава и использует публичные
  компоненты `features/products`. Локальный ингредиент создаётся в footer overlay поиска; для новых
  строк барная ложка не предлагается, но сохранённое ранее значение остаётся видимым. Подписи единиц
  в строке состава и поля фактического выхода — «Кол-во» и «Ед. изм.».
- `usePreparations.ts` владеет TanStack Query-запросами и ключами `preparation-list`,
  `preparation-card` и `product-references`, а также синхронизацией поиска и категории с URL.

Действие безвозвратного удаления доступно при `delete_products_permanently`. При активных ссылках
пользователь может выбрать одну замену сразу для всех связей или явно удалить всю зависимую локальную
цепочку; индивидуальные замены не настраиваются, архивные ссылки блокируют замену. Короткое удаление
без зависимостей не требует ввода названия.

Маршрут списка: `/app/companies/:companyId/venues/:venueId/preparations`; параметр `preparation`
в query выбирает карточку и сохраняет контекст фильтрации. Старый маршрут
`/app/companies/:companyId/venues/:venueId/preparations/:preparationId` остаётся совместимым и
открывает тот же список с Drawer. Создание и редактирование открываются в Drawer; закрытие
карточки сохраняет остальные query-параметры. Backend остаётся источником прав и ограничений области
данных; frontend показывает действия создания и редактирования только при `manage_products`.

При сохранении изменённой заготовки backend в одной транзакции проверяет прямые и косвенные
зависимости активной продукции текущего заведения. Если они есть, он возвращает список влияния
без записи. После подтверждения сервер повторно проверяет список и сохраняет только при
актуальном отпечатке; изменившийся список требует нового подтверждения. Неизменённая форма
не отправляется. Ошибки остаются вверху Drawer, введённые данные сохраняются.

При закрытии изменённой формы кнопкой, крестиком, Escape или затемнённой областью показывается
PrimeVue Dialog подтверждения; во время сохранения Drawer остаётся открытым.

После изменения HTTP-контракта API-клиент обновляется только штатной командой
`pnpm api:generate`; generated-файлы вручную не редактируются.
