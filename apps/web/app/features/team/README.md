# Команда компании и заведения

Срез `team` содержит два отдельных маршрута рабочего заведения. `/schedule` показывает композицию `TeamManagementScreen.vue` с графиком `ScheduleScreen`; управление сотрудниками доступно на отдельной странице. Старый адрес `/team` перенаправляет на `/schedule`. `/team/management` доступна бар-менеджеру и показывает таблицу сотрудников и размещённые справа формы приглашения и увольнения. На широком экране таблица занимает 65% рабочей области, правая колонка — 35%; между колонками используется штатный `Divider`. В правой колонке приглашение и увольнение расположены вертикально через `Divider`. На узком экране области складываются вертикально. Таблица заполняет высоту левой области и прокручивает строки внутри себя, показывая только ФИО и должность. Нажатие на строку открывает Drawer редактирования должности и персональных разрешений; в Drawer показан полный набор прав сотрудника. Увольнение доступно только в отдельном блоке.

Приглашение шеф-бармена и приглашения сотрудников заведения используют разные API и области членства. `useCompanyChefTeam` обслуживает компанию, `useVenueTeam` — текущее заведение. Форма предлагает только должности, разрешённые для текущего пользователя, а обработчик направляет запрос по выбранной должности. Отзыв приглашений также вызывает API соответствующего контекста. Создание нового заведения остаётся в срезе управления заведениями.

`useVenueTeam` загружает членов команды и приглашения, создаёт и отзывает приглашения, изменяет сотрудника и планирует увольнение. API отдаёт первый нерабочий день, совпадающий с исключительной границей членства. После подтверждения query команды, рабочего пространства и графика инвалидируются. `useCompanyChefTeam` обслуживает приглашения шеф-барменов на уровне компании. Состав сотрудников и должности отображаются в графике по датам действия периодов членства и ролей. Страница управления показывает приглашения и увольнение по серверным разрешениям. Назначение сотрудника шеф-барменом доступно только действующему шеф-бармену; новый шеф-бармен присоединяется по приглашению. Роль подтверждается отдельным запросом сразу, а сохранение персональных разрешений выполняется независимо.

Список шеф-барменов компании отдельно не отображается; приглашения шеф-барменов по-прежнему включены в список ожидающих приглашений компании. В режиме разработки список сотрудников дополняется локальным общим roster предпросмотра графика; эти строки не отправляются в API, а изменения редактора применяются только локально. В production моковые строки отсутствуют. Режим предпросмотра графика не подменяет данные команды и API увольнения.

Оба вида приглашений проходят публичный поток `/invitations`: токен остаётся во fragment до чтения клиентом и не попадает в HTTP URL, а членство создаётся только после завершения регистрации или входа. Приглашение шеф-бармена создаёт роль уровня компании без локального членства; остальные должности относятся к выбранному заведению. Сроки, состояния и обработка конфликтов описаны в `REGISTRATION_FLOW.md`, состав ролей — в `ROLES_AND_PERMISSIONS.md`, а технические поля — в `DATA_MODEL.md`.

Бизнес-правила ролей и областей доступа описаны в [ROLES_AND_PERMISSIONS.md](../../../../../ROLES_AND_PERMISSIONS.md); актуальное представление экрана — в [UI_AND_NAVIGATION.md](../../../../../UI_AND_NAVIGATION.md).
