# Команда компании и заведения

Срез разделяет локальную команду заведения и шеф-барменов компании. Локальные сотрудники и приглашения управляются только в контексте выбранного заведения; приглашение шеф-бармена относится к компании и предоставляет доступ ко всем её заведениям.

`useVenueTeam` и `useCompanyChefTeam` загружают соответствующие составы через сгенерированный API-клиент, создают и отзывают приглашения. `TeamManagementScreen` показывает локальную команду заведения, а отдельный `ChefTeamSection` — команду и приглашения шеф-барменов компании. Области членства, подписи и API остаются раздельными; объединена только точка входа. Старый маршрут шеф-барменов перенаправляет на команду. `TeamMemberList` показывает роли и доступное управление; `TeamMemberEditorDrawer` позволяет изменить локальную должность и отдельные группы делегируемых прав. При изменении должности права этого сотрудника в заведении сбрасываются; пользователь видит предупреждение до сохранения. `useVenueTeam` отправляет один запрос на сохранение обеих частей и обновляет список после ответа. Для сохранения прав фронтенд использует публичный тип тела операции API; ответ сервера остаётся более широким (`string[]`), поэтому перед повторной отправкой в форму попадают только известные коды прав.

Backend рассчитывает доступные действия для представления, но это не является авторизацией. Каждый запрос на изменение повторно проверяет инициатора, область компании и заведения, ограничения временного ответственного и актуальную непрерывность управления. Запись роли, права и событие аудита выполняются атомарно. Себя нельзя редактировать через карточку; ограничения выхода описаны отдельно в `ROLES_AND_PERMISSIONS.md`.

Для новых событий изменения роли, делегирования прав и окончания временной ответственности
сохраняется UUID субъекта членства в минимальных метаданных. Это позволяет журналу показать
сотруднику адресованное ему изменение, не восстанавливая адресата по удалённому членству.

Оба вида приглашений проходят единый публичный поток `/invitations`: токен остаётся во fragment до чтения клиентом и не попадает в HTTP URL, а постоянное членство создаётся только после завершения регистрации или входа. Приглашение шеф-бармена создаёт роль уровня компании без локальных членств; он перенаправляется в доступное заведение компании. Сроки, состояния и конфликты определены в `REGISTRATION_FLOW.md`, роли — в `ROLES_AND_PERMISSIONS.md`, технические поля — в `DATA_MODEL.md`.
