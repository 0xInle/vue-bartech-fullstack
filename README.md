# IndieBar

IndieBar — адаптивное PWA для барной команды. Репозиторий содержит Nuxt-приложение, NestJS API и общие технические пакеты в одном `pnpm` workspace.

## Требования

- Node.js 24 LTS; точная локальная версия закреплена в `.node-version`.
- pnpm 11.19.0; версия закреплена в корневом `package.json`.
- Docker с Compose plugin.

## Локальный запуск

```sh
pnpm install
cp .env.example .env.local
pnpm infra:up
pnpm dev
```

Локальная база называется `indiebar`. Роль подключения PostgreSQL пока называется `bartech` — это
отдельная учётная запись, не имя базы; она сохранена, чтобы не менять учётные данные уже созданного
Docker-тома. Если том PostgreSQL был создан до перехода с `bartech`, команда `pnpm infra:up`
сохранит старую базу и её данные, но не создаст новую автоматически: создайте пустую базу `indiebar`
командой `docker compose --env-file .env.local -f infrastructure/compose.yaml exec postgres createdb -U bartech indiebar`,
затем примените миграции и при необходимости начальные данные отдельными командами проекта.

Nuxt запускается на `http://localhost:3000`, NestJS API — на `http://localhost:3001/api/v1`. Локальный Nuxt proxy направляет `/api` в NestJS, поэтому клиент использует same-origin URL и переносит cookie в SSR-запросах. Документация OpenAPI доступна в режиме разработки по адресу `http://localhost:3001/api/docs`.

Для фоновой отправки писем и ежедневного сопоставления локальных ингредиентов откройте отдельный терминал и выполните `pnpm dev:worker`. Worker собирается отдельно от API, поэтому процессы разработки не очищают файлы сборки друг друга. Сопоставление планируется на 06:00 по Москве (`Europe/Moscow`); расписание создаётся только worker-процессом. Локальные сервисы можно остановить командой `pnpm infra:down`; именованные тома при этом сохраняются. Все порты инфраструктуры привязаны только к `127.0.0.1`. Mailpit доступен на порту `8025`.

В `.env.local` для локальной разработки используются `APP_ORIGIN=http://localhost:3000`, SMTP Mailpit (`MAIL_HOST=localhost`, `MAIL_PORT=1025`, `MAIL_SECURE=false`) и `OUTBOX_ENCRYPTION_KEY` — base64-представление 32 байт. Значение из `.env.example` предназначено только для локальной среды. Для production нужен отдельный случайный секрет. Payload письма шифруется AES-256-GCM в Outbox и удаляется после доставки или окончательного отказа; ключ и содержимое письма не логируются.

### Объектное хранилище для разработки

`pnpm infra:up` запускает локальное S3-совместимое хранилище SeaweedFS на `http://localhost:9000` и создаёт в нём бакет из `S3_BUCKET`. Ключи `S3_ACCESS_KEY` и `S3_SECRET_KEY` из `.env.local` используются локально как учётные данные хранилища; шаблон `.env.example` содержит безопасные значения только для разработки. Файлы сохраняются в Docker-томе и остаются после `pnpm infra:down`.

В production используется отдельный приватный бакет Yandex Object Storage и отдельные учётные данные. Production-секреты не добавляются в Git. `.env.local` хранит локальные настройки разработчика и не перезаписывается командами проекта.

## Статические проверки

```sh
pnpm lint
pnpm typecheck
pnpm prisma:validate
pnpm api:generate
pnpm api:check
pnpm build
```

Автоматические тесты в MVP не создаются и не запускаются без прямого согласования владельца продукта.

Команда `pnpm verify` объединяет только перечисленные выше статические проверки и production-сборку; тесты и запуск контейнеров она не выполняет.

Сгенерированные API-запросы и Vue Query composables находятся в `packages/api-client`. В Nuxt для них используется `useApiFetch()`, который сохраняет same-origin адреса, передаёт cookie в SSR и поддерживает переопределение адреса через `NUXT_PUBLIC_API_BASE_URL`.
